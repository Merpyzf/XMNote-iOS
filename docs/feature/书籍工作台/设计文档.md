# 书籍工作台设计文档

## 设计结论

“书籍工作台”是围绕单本书组织资料、阅读概览和四类内容管理的核心页面，不是单纯的“书籍详情页”或“书摘列表页”。当前代码保留 `BookDetailView` 入口名称，新增实现统一使用 `BookWorkspace*` 语义。

页面实现采用“SwiftUI 负责业务状态与路由，UIKit 负责高频分页和列表几何”的混合结构。其目的不是复刻 Android 视图层，而是对齐业务信息和交互意图，同时保留 iOS 当前视觉风格。

## 真实 owner 与触发链路

| 层级 | 真实 owner | 负责内容 | 主要触发时机 |
| --- | --- | --- | --- |
| 页面入口 | `BookDetailView` | 注入书籍 ID、路由回调、隐藏外层 Tab Chrome | 进入/离开单书路由 |
| 业务状态 | `BookDetailViewModel` | 观察书籍、书摘、相关分类、相关内容、书评和封面主题色 | 页面出现、数据库观察流更新、封面变化 |
| 展示派生 | `BookWorkspacePresentationStore` | 搜索、筛选、排序、分组和 Diffable Snapshot 构建 | 输入域真实变化、搜索词变化 |
| 页面组合 | `BookWorkspaceContentView` | 当前内容域、工具栏、加载门闩和路由分发 | 用户交互、加载状态变化 |
| 原生宿主 | `BookWorkspaceCollectionHostView` | 四页常驻、共享头部/Tab、分页、吸顶、视口稳定 | 布局、滚动、快照更新、主题变化 |
| Tab 几何 | `BookWorkspaceScopeBarView` | 标题、数量、指示线和可见区域 | Pager 连续位置、布局完成、外部选中态同步 |

## 数据链路

1. `BookReadQuery.fetchBook` 从 Android canonical 数据结构读取书籍详情。
2. 查询同时聚合阅读时长、有效读完次数和四域数量，并格式化书签、进度与多刷状态文案。
3. `BookDetail` 作为稳定展示模型承载头部和四域所需字段。
4. `BookDetailViewModel` 通过 Repository observation 接收最新值，并在后台派生富文本纯文本预览和封面主题色。
5. `BookWorkspacePresentationStore` 只对发生变化的内容域重建不可变快照，以 revision 拒绝过期结果。
6. `BookWorkspaceCollectionHostView` 将快照应用到四个常驻 `UICollectionView`，业务 Item 使用稳定 ID，不使用数组下标作为身份。

## 页面结构

### 1. 背景层

- `BookWorkspaceHeaderBackdropView` 负责可越过顶部安全区的封面主题氛围。
- 背景色和渐变色使用 Core Animation 属性更新；主题切换允许 0.18 秒淡入淡出。
- 背景不承载交互，不参与指示线或标题快照。

### 2. 共享 Chrome

- `BookWorkspaceBookHeaderHostView` 和 `BookWorkspaceScopeBarView` 各只有一个实例。
- 四个列表只保留等高的 `chromeSpacer`，实际头部和 Tab 由宿主覆盖渲染。
- 共享头部真实高度由 SwiftUI Hosting Content 的 fitting size 测量，并同步到四页占位。
- 当前页和相邻页的纵向滚动量在横向分页时插值，统一决定背景、头部与 Tab 的 Frame。

### 3. 内容 Pager

- `UIScrollView` 作为横向 Pager，四个 `UICollectionView` 通过 content/frame layout guide 串成等宽页面。
- 每个内容域保留独立 Collection、diff、滚动位置和预热任务。
- 分页移动时只有起始页和目标页参与交互与预取；页面对象本身始终常驻。
- 左边缘返回手势优先于横向分页，避免页面私有手势破坏系统导航。

### 4. 内容列表

- 目录、相关、书评使用分组行布局。
- 书摘使用独立不透明卡片，并按章节创建可吸顶 supplementary header。
- 单条书摘展开状态由 `BookWorkspaceNoteRowState` 按 Note ID 持有，避免一条内容展开使整页重新计算。
- 搜索变化使用 150ms 去抖；页面退出时取消展示派生和富文本预处理任务。

## 书籍头部数据规则

| 数据项 | 来源 | 显示规则 |
| --- | --- | --- |
| 书名 | `book.name` | 始终展示，最多两行 |
| 作者 | `book.author` | 非空展示；作者/译者组合为独立事项 |
| 出版社 | `book.press` | 非空展示 |
| 出版日期 | `BookDetailAttribute.pubDate` | 非空且不等于 `1970-01-01` 时展示 |
| 封面 | `book.cover` | 使用 `XMBookCover` |
| 阅读状态 | `readStatusID` + `readStatusBadgeTitle` | 文案保留多刷语义，颜色由状态 ID 决定 |
| 阅读时长 | `totalReadingSeconds` | 大于 0 才展示，按小时/分钟/秒保留有效单位 |
| 评分 | `score` | 大于 0 才展示 |
| 书签 | `bookmarkText` | 非空展示 |
| 阅读进度 | `readingProgressText` | 非空展示，可与书签同时出现 |

头部指标保持 iOS 的横向图标样式和现有点击行为。书摘数量不在头部重复展示。

## Tab 指示线设计

### 问题归因

录屏中的偏移不是标题和指示线一起进入，而是主题变化曾对整个 Tab 容器执行交叉溶解，旧容器快照包含一条旧指示线；同时真实指示线已按新几何落位，于是短时间内出现两个视觉实例。

### 三个基本约束

1. 数据加载和主题取色不是 Tab 选择行为，不能动画整个 Tab 容器。
2. 指示线只有在容器、滚动视口和标题锚点均为非零有限几何时才可显示。
3. 指示线运动只由用户分页位置驱动；首次布局和尺寸重算必须立即校准。

### 当前实现

- 主题更新仅动画 `backgroundColor`，不再对 `BookWorkspaceScopeBarView` 做 `UIView.transition`。
- 指示线初始化隐藏；几何无效时继续隐藏。
- `displayedPagePosition` 保存最近一次真实分页位置，`layoutSubviews` 根据该位置重新计算 Frame。
- Frame 和显隐统一包在 `UIView.performWithoutAnimation` 中，避免继承导航或主题动画事务。
- `scrollViewDidScroll` 将 Pager 连续位置直接传给 Scope Bar，指示线不启动独立位移动画。
- Scope Bar 刷新输入收窄为 items、committed section、Reduce Motion 和 palette ID；书籍头部其它字段变化不触发无意义重配。

## 状态提交边界

- `committedSection` 是业务已选域，只在分页真正落定后提交。
- `requestedSection` 是用户点击 Tab 后的临时目标，不提前改变业务工具栏。
- `BookWorkspacePagerPosition` 是 UIKit 内部连续值，只服务标题颜色、指示线、共享 Chrome 插值和预取策略。
- SwiftUI 只接收最终 section 和“头部是否完全收起”的阈值布尔值，避免逐帧状态写入。

## Android 对齐策略

- 对齐 Android 的页面职责、四域顺序、头部数据项和有效值规则。
- 不复刻 `CollapsingToolbarLayout`、`TabLayout`、`ViewPager2` 的具体样式；iOS 使用共享 Chrome、原生 Pager 和系统导航手势表达相同业务意图。
- 数据库读完次数严格采用 Android `book_read_status_record` 的软删除和状态过滤口径。
- Android 头部的书摘数量按产品决策在 iOS 头部省略，因为 Tab 已提供同类数量信息。

## 风险与守护条件

- 不得把连续滚动位置提升为 SwiftUI `@State`，否则会扩大高频重绘范围。
- 不得为四个内容域各创建一套书籍头部或 Tab，否则会重新引入重复实例与切页跳变。
- 不得使用延迟隐藏、固定偏移或等待转场结束等遮盖式方案修复指示线。
- 动态字体或旋转后必须重新测量共享 Chrome 高度，并以当前连续分页位置无动画落位。
- 新增头部信息项时，先补 `BookDetail` 数据链路和有效值规则，再进入视图层。
