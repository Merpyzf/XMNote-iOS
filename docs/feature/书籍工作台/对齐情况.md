# 书籍工作台 iOS ↔ Android 对齐情况

评估日期：2026-08-17

## 口径说明

- 整页统一称为“书籍工作台（Book Workspace）”。
- iOS 代码入口仍为 `BookDetailView`；Android 代码入口为 `NoteManagerActivity`。类名不作为产品页面名称。
- 本文对齐的是业务信息项和交互意图，不要求双端布局与视觉样式一致。
- 书摘数量允许在 iOS 头部省略；作者与译者组合展示按独立事项评估。

## 功能点清单

### 1. 单书内容工作台入口

- 功能点：进入一本书后，在同一页面管理书籍概览与四类内容。
- iOS 行为：`BookDetailView` 创建单书状态源并挂载 `BookWorkspaceContentView`，页面统一承接书籍头部、目录、书摘、相关和书评。
- Android 行为：`NoteManagerActivity` 绑定书籍 Header，并创建目录、书摘、相关、书评四个 Fragment。
- 对齐状态：已对齐。
- 双端代码证据：

### 2. 四域顺序与默认域

- 功能点：固定展示目录、书摘、相关、书评，并默认进入书摘。
- iOS 行为：`BookWorkspaceSection` 固定四域顺序，页面 `selectedSection` 默认 `.notes`。
- Android 行为：`tabTitles` 固定相同顺序，ViewPager 通过保存的 `selectedTabPosition` 无动画恢复当前页。
- 对齐状态：已对齐。

### 3. 头部书名、作者、出版社、出版日期和封面

- iOS 行为：展示书名、非空作者、封面；出版社和有效出版日期使用 ` · ` 组成一行，日期为空或 `1970-01-01` 时不显示。
- Android 行为：分别绑定书名、作者、出版社、出版日期和封面；空文本隐藏，出版日期同时排除 Unix 起始占位值。

### 4. 作者与译者组合展示

- 功能点：作者在前、译者在后并使用 `/` 分隔。
- iOS 行为：当前 Header 只展示 `book.author`；详情查询已读取译者并保留在属性列表，但没有组合到 Header。
- Android 行为：当前 Header Binder 同样只绑定 `book.author`，不展示译者。
- 对齐状态：未对齐，且不在本轮实施范围。
- 双端代码证据：
  - iOS：`xmnote/Data/Repositories/BookReadQuery.swift:143`、`xmnote/Data/Repositories/BookReadQuery.swift:167`、`xmnote/Views/Book/Components/BookWorkspaceCollectionView.swift:2284`

### 5. 阅读状态与多刷文案

- 功能点：显示当前阅读状态，并在重读场景展示“2 刷”“2 刷中”等文案和正确状态色。
- iOS 行为：详情 SQL 按 `is_deleted = 0`、目标 `book_id`、`read_status_id = 3` 统计读完次数；文案由共享 Formatter 生成，颜色由 `readStatusID` 判定。
- Android 行为：状态徽标按当前状态 ID 着色，使用读完次数生成多刷文案；DAO 的状态次数查询采用相同软删除、书籍和状态过滤。
- 对齐状态：已对齐。
- 双端代码证据：

### 6. 阅读时长

### 9. 头部书摘数量

- 功能点：是否在书籍信息头部重复展示书摘数量。
- iOS 行为：头部不展示书摘数量，Tab 中保留书摘数量。
- Android 行为：头部阅读统计区在书摘数量大于 0 时展示，同时 Tab 提供对应内容域入口。
- 对齐状态：有意差异。
- 双端代码证据：
  - iOS：`xmnote/Views/Book/Components/BookWorkspaceCollectionView.swift:2375`、`xmnote/Views/Book/Components/BookWorkspaceCollectionView.swift:1463`

- 评估结论：功能优化。产品已明确允许忽略头部书摘数量，iOS 通过 Tab 数量避免重复信息。
- Android 反向建议：
  - 是否吸收：可选。
  - 建议优先级：低。
  - 风险：低。若移除头部数量，需要确认 Tab 数量在全部字号和横屏下仍可见。

### 10. 头部收起、Tab 吸顶与横向分页

- 功能点：纵向浏览时收起书籍信息并固定 Tab，横向切换四个内容域。

- Android 行为：`CollapsingToolbarLayout`/`AppBarLayout` 管理头部收起，`TabLayoutMediator` 连接 TabLayout 与 ViewPager2。
- 对齐状态：已对齐，展示实现为平台原生差异。

### 11. Tab 指示线与主题动画边界

- 功能点：指示线只跟随真实分页位置，不在进入页面或主题变化时出现偏移残影。
- iOS 行为：Scope Bar 只动画背景色；指示线在标题几何有效后显示，Frame 和显隐无动画更新，Pager 的 `contentOffset` 连续驱动其位置。
- Android 行为：Tab 指示线由 `TabLayoutMediator` 和 ViewPager2 的页面位置驱动，且关闭 full-width 指示器。
- 对齐状态：已对齐。
- 双端代码证据：

### 12. 内容域生命周期与滚动位置

- 功能点：切换内容域后保留已浏览位置。
- iOS 行为：四个 Collection 全部常驻，只对当前过渡涉及的页面开放交互和预取。
- Android 行为：ViewPager2 使用 Fragment Adapter，并设置 `offscreenPageLimit = 1`；相邻页保活，其余页由 Fragment 生命周期管理。
- 对齐状态：有意差异。
- 双端代码证据：
  - iOS：`xmnote/Views/Book/Components/BookWorkspaceCollectionView.swift:943`、`xmnote/Views/Book/Components/BookWorkspaceCollectionView.swift:995`、`xmnote/Views/Book/Components/BookWorkspaceCollectionView.swift:1338`
  - Android：`/Users/wangke/Workspace/AndroidProjects/XMNote/app/src/main/java/com/merpyzf/xmnote/ui/note/activity/NoteManagerActivity.kt:983`
- 评估结论：功能优化。iOS 用四页常驻换取稳定滚动位置，并通过资源策略限制非活动页预取。
- Android 反向建议：
  - 是否吸收：否。
  - 建议优先级：低。
  - 风险：中。Android Fragment 状态恢复已由平台管理，扩大保活范围会增加内存压力。

## 总结

- iOS 书籍工作台已对齐 Android 的核心页面职责、四域顺序和除作者/译者外的头部有效数据项。
- 书摘数量是经确认的头部信息去重；四页常驻是 iOS 为滚动连续性采用的平台化实现。
- 当前唯一明确未完成的数据项是“作者 / 译者”组合展示，应继续按独立方案推进，不能在本轮文档中标记为已完成。
