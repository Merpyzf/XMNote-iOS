# 单书工作台 - 设计文档

## 1. 最终结构

- 页面壳：`xmnote/Views/Book/BookDetailView.swift`
- 原生列表：`xmnote/Views/Book/Components/BookWorkspaceCollectionView.swift`
- 书摘卡片：`xmnote/Views/Book/Components/BookWorkspaceNoteItem.swift`
- 展示派生：`xmnote/ViewModels/Book/BookWorkspacePresentationStore.swift`
- 页面状态：`xmnote/ViewModels/Book/BookDetailViewModel.swift`
- 数据读取与写入：`BookRepository`、`ContentRepository`、`BookContentSortQuery`

旧 `BookContentWorkspaceView` 已移除，避免 SwiftUI 与 UIKit 两套实现产生行为漂移。

## 2. 展示管线

```text
Repository 观察流
  -> BookDetailViewModel（页面业务状态）
  -> BookWorkspacePresentationInput（值语义输入）
  -> BookWorkspacePresentationStore（可取消派生）
  -> diffable snapshot
  -> 四个常驻 UICollectionView
```

- 每个内容域独立 revision 和任务；发布前核对 revision 与取消状态。
- Item 身份使用数据库主键，禁止数组下标进入 diff identity。
- 收起态富文本使用 `CollapsedRichTextPreview`，完整态使用 `RichText`。
- 书摘富文本布局可预热，页面销毁时取消预热任务。

## 3. 排序与筛选

- `BookContentSortRule` 是唯一持久化排序语义。
- `BookContentSortType` 按 Android 常量区分 NOTE/RELEVANT/REVIEW，互不串值。
- Repository 负责最终排序；展示层只搜索、分组并保持 Repository 顺序。
- `CatalogFilter`、搜索词、“只看有想法”属于页面局部状态，不写数据库。

## 4. 写入与导航

- View 只调用 `BookDetailViewModel` 或根级 `AppNavigationCoordinator`，不直接访问数据库。
- 编辑器和 Viewer 使用根级全屏任务，关闭后保留书籍 Tab 原现场。
- 目录管理使用当前 Tab 的 `BookRoute.chapterManager`。
- 删除通过 `ContentRepository` 单事务软删除主记录和子记录；书摘导入哈希按 Android 物理清理。

## 5. 并发约束

- ViewModel 的观察、纯文本预处理、颜色解析和工作区任务均可取消。
- UIKit/TextKit 测量留在主线程；HTML 纯文本派生可在可取消后台任务执行。
- 写操作使用门闩，防止排序、删除和关系编辑并发覆盖。
