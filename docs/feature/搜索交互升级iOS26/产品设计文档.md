# XMNote 全局搜索产品设计文档 v1.0

## 1. 产品定位与目标

XMNote 的全局搜索应定位为“用户找回本地阅读资产的最快入口”，覆盖书籍、书摘、想法、相关内容、书评和阅读记录信息。它不是单纯的数据库筛选，也不是书籍搜索页，而是帮助用户在大量个人阅读内容中快速完成“我记得某本书 / 某句话 / 某个想法 / 某段关联资料在哪里”的任务。

本次优化目标：

- 提升搜索命中后的判断效率，让用户不用点进详情也能判断是不是要找的内容。
- 保留 Android 已有的 `书籍 / 书摘 / 相关 / 书评` 全局搜索能力。
- 在 iOS 上保持系统原生、干净、轻量，不照搬竞品的暗色、高饱和蓝色胶囊和强数字标签。
- 强化 XMNote 自己的阅读记录属性：阅读状态、来源、进度、最近阅读时间、标签、书摘上下文。
- 降低单字搜索、高频词搜索时的结果压力。

## 2. 用户场景与核心问题

### 场景 A：找一本读过或正在读的书

用户想找“AI工程”，但只记得书名里有 AI。
理想体验：输入 `AI` 后先看到书籍类结果，结果卡展示封面、书名、作者、出版社、ISBN、阅读状态、来源和最近阅读信息。用户一眼知道这是不是自己书架里的那本。

当前问题：iOS 已经能显示书籍结果，但阅读状态和来源信息不足，搜索结果更像“书目信息”，不够像“我的阅读资产”。

### 场景 B：找一句曾经摘录过的话

用户记得自己摘过一句包含“我”的话，但不知道在哪本书。
理想体验：进入书摘结果后，可以进一步缩小到 `正文 / 想法 / 书名 / 标签`，正文片段中关键词清晰高亮，并展示所属书籍和时间。

当前问题：iOS 有书摘结果，但缺少字段级范围筛选。单字搜索时容易被大量正文结果淹没。

### 场景 C：找一个想法或心得

用户记得自己在某条书摘下写过关于“写作”的想法。
理想体验：搜索后进入书摘分类，切到“想法”范围，只看自己写的心得内容，不被正文原文干扰。

当前问题：Android 和 iOS 都能搜正文/想法，但产品层没有把“正文”和“想法”作为用户可理解的筛选入口。

### 场景 D：找相关资料或书评

用户记得自己给一本书关联过一篇资料，或者写过一段书评。
理想体验：搜索结果能进入 `相关 / 书评`，分别展示标题、摘要、图片、所属书籍、时间，用户能判断资料类型和上下文。

当前问题：iOS 已经覆盖相关和书评，但结果页需要更稳定地呈现内容身份，避免和书摘结果混淆。

### 场景 E：没有搜到书，顺手添加

用户搜索某本书，发现本地没有。
理想体验：只有在“书籍”分类无结果时，才给出轻量的“添加书籍”入口。全局无结果时不直接诱导添加书，避免误导。

当前问题：竞品截图里“已搜到书籍但底部仍提示没搜到并添加新书”的状态冲突需要避免。

## 3. 产品设计原则

- 全局优先：先让用户输入一个词看到所有本地内容，再提供分类和字段缩小范围。
- 判断优先：结果卡片要帮助用户判断“是不是我要找的”，而不是展示调试式命中说明。
- 克制表达：不显示“最佳匹配 / 共 N 条 / 命中 / 查看更多”这类偏 B 端文案。
- 原创视觉：不复制竞品的暗色主题、亮蓝胶囊、强计数标题和底部悬浮添加条。
- 阅读资产感：书籍结果不只是书目信息，还要体现阅读状态、来源、进度、最近阅读。
- 本地可信：搜索范围以本地数据为主，强调私密、快速、可离线。

## 4. 功能方案

### 4.1 搜索入口与根页

设计方案：

- 底部保留 iOS 26 系统 Search Tab 搜索框，placeholder 为 `搜索本地内容`。
- 搜索根页顶部只显示标题 `搜索`。
- 无历史时，页面中部显示轻提示：`输入关键词 / 查找你的本地内容`。
- 有真实历史时，显示 `最近搜索`，最多 8 个 chip，按最近使用排序。
- 不展示“可搜索范围”说明卡，不展示大插画，不展示假历史。

用户场景：

用户昨天搜过“百年孤独”，今天想继续找相关书摘。进入搜索页后直接点击历史词，无需重新输入。

验收标准：

- 无历史时页面干净，不出现分类说明。
- 有历史时只展示真实提交过的搜索词。
- 点击历史词后填入搜索框并触发搜索。

### 4.2 输入与搜索触发

设计方案：

- 中文输入组合态不触发搜索，例如输入 `wo` 但候选词还没确认时不搜索。
- 候选词确认后触发搜索。
- 输入变化采用短 debounce，避免每输入一个拼音字母都刷新。
- 快速删除到空关键词时回到根页。
- 读取加载采用延迟显示，快速搜索不闪 loading。

用户场景：

用户想搜“我”，先输入 `wo`。在候选栏还没选“我”时，页面保持根态；确认“我”后才展示结果，避免出现无意义的 `wo` 搜索。

验收标准：

- 拼音组合态不发起搜索。
- 确认候选后结果更新。
- 快速输入、清空、重新输入时没有旧结果残影。

### 4.3 一级分类：全局内容范围

设计方案：

- 一级分类固定使用 Android 已有业务范围：`书籍 / 书摘 / 相关 / 书评`。
- 只显示有结果的分类。
- 如果只有一个分类有结果，隐藏分类栏，直接展示列表。
- 不提供 `全部` 聚合页，避免混排造成信息结构复杂。
- 分类顺序固定：书籍、书摘、相关、书评。

用户场景：

用户搜索 `AI`，本地只命中书籍和书摘。页面只显示 `书籍 / 书摘`，用户不会看到空的 `相关 / 书评` 干扰判断。

验收标准：

- 分类栏不显示空分类。
- 分类切换不清空搜索词。
- 返回搜索页后保留上次分类。

### 4.4 二级范围筛选：字段级缩小范围

设计方案：

在一级分类结果较多时，显示二级范围筛选。视觉上使用 XMNote 自己的轻量 chip，不使用竞品的大蓝色计数胶囊。

推荐范围：

- 书籍：`书名 / 作者 / 出版社 / 标签 / ISBN`
- 书摘：`正文 / 想法 / 书名 / 标签`
- 相关：`标题 / 内容 / 书名 / 分类`
- 书评：`标题 / 正文 / 书名`

显示规则：

- 当前分类结果少于 8 条时默认隐藏二级筛选。
- 当前分类结果较多，或命中字段超过 2 类时显示。
- 二级筛选可以显示弱计数，但数字不作为主视觉，例如 `正文` 后跟很轻的辅助数字。
- 不显示“命中字段”说明文案。

用户场景：

用户搜索“我”，书摘结果很多。用户切到 `想法`，只看自己写过的心得，快速排除书籍原文中的大量“我”。

验收标准：

- 二级筛选只在当前分类内部生效。
- 切换二级筛选时不跳回顶部以外的页面层级。
- 清空搜索词后一级、二级筛选都消失。

### 4.5 书籍结果卡片

设计方案：

书籍结果展示：

- 封面
- 书名
- 作者
- 译者
- 出版社
- ISBN
- 阅读状态：在读、已读、想读、闲置等
- 来源：本地、微信读书、导入、手动录入等
- 阅读进度或最近阅读时间，有值时显示
- 创建时间弱化到右下角或次级位置

展示规则：

- 书名为第一层级，关键词高亮。
- 作者、译者、出版社、ISBN 只在有值时展示。
- 阅读状态和来源用 XMNote 自己的 chip 风格，不复制竞品紫色/蓝色标签。
- 不显示 `命中：书名`、`位置：作者`。

用户场景：

用户搜索 `AI`，看到一本《AI工程》。卡片显示它是“在读”、来源是“本地导入”、最近读到 57 页。用户立即确认这是自己正在读的那本，而不是网络搜索结果。

验收标准：

- 书籍卡片能回答三个问题：是哪本书、为什么搜到、我和它的阅读关系是什么。
- 长书名最多展示 2 行。
- 缺少作者或 ISBN 时不留空占位。

### 4.6 书摘结果卡片

设计方案：

书摘结果展示：

- 摘录正文，第一阅读层级
- 想法，有值时作为次级轻底色内容块
- 图片缩略图，有图时显示
- 标签，有标签时显示
- 底部展示所属书籍 `《书名》` 和时间
- 可补充页码、进度或章节信息，有值时显示

展示规则：

- 正文关键词使用“轻底色 + 品牌强调色”高亮，不复制竞品蓝底白字。
- 想法区低于正文层级，避免抢主内容。
- 列表默认不常驻分享、更多、编辑按钮。
- 点击整条进入详情，并自动定位到命中片段。

用户场景：

用户搜索“母亲”，想找之前摘过的一段话。列表展示正文片段，关键词被高亮，底部显示《日本制造：盛田昭夫的日式经营学》和时间。用户不用点开就能判断这是不是要找的句子。

验收标准：

- 正文片段可读，不因高亮破坏阅读节奏。
- 有想法、图片、标签时自然展示；没有时不占位。
- 点击进入详情能看到同一命中上下文。

### 4.7 相关内容结果卡片

设计方案：

相关内容分两类展示：

- 普通相关内容：标题、摘要、图片、分类、所属书籍、时间
- 相关书籍：封面、书名、作者、译者、出版社、ISBN、来源书籍、时间

展示规则：

- 页面只显示类目名 `相关`，不写“可能相关”“相关依据”。
- 普通相关内容和相关书籍使用不同卡片结构，避免混淆。
- 内容摘要关键词高亮。
- 所属书籍作为底部上下文。

用户场景：

用户搜索“写作”，之前给某本书关联过一篇写作方法资料。相关结果显示资料标题、摘要、分类和所属书籍，用户知道这是资料，不是书摘原文。

验收标准：

- 相关内容和相关书籍在视觉上能区分。
- 所属书籍始终可见。
- 点击后进入对应相关详情或书籍详情。

### 4.8 书评结果卡片

设计方案：

书评结果展示：

- 书评标题，有值时显示
- 正文摘要
- 图片缩略图，有图时显示
- 所属书籍
- 时间

展示规则：

- 标题为主层级，正文摘要为次层级。
- 标题或正文命中都高亮。
- 不显示 `书评命中`。
- 点击进入书评详情，保留搜索返回上下文。

用户场景：

用户记得自己写过一段关于“创新”的书评，但忘了是哪本书。搜索后进入 `书评`，看到标题、摘要和所属书籍，快速定位到那条评论。

验收标准：

- 无标题书评以正文摘要作为主判断信息。
- 有图片时展示缩略图，但不压缩文字可读性。
- 返回后保留搜索状态。

### 4.9 高亮与摘要策略

设计方案：

- 使用 XMNote 品牌强调色，不使用红色，不复制竞品蓝底样式。
- 高亮策略为轻底色或强调色文字，保证浅色模式下自然。
- 摘要优先截取关键词前后上下文。
- 同一条结果中多个命中，只高亮可见片段内的命中。
- 不展示“第几个命中”这类工具型信息。

用户场景：

用户搜索“AI应用”，书名和出版社都可能包含关键词。卡片只在实际文字中高亮，不额外解释命中字段，用户自然理解为什么出现。

验收标准：

- 高亮可识别但不刺眼。
- 红色只用于错误、删除、警告。
- 长文本摘要能包含关键词上下文。

### 4.10 无结果与添加书籍入口

设计方案：

- 全局无结果：显示 `没有找到内容 / 换个关键词再试`。
- 书籍分类无结果：显示 `没有找到这本书`，可提供轻量 `添加书籍` 入口。
- 只有当用户当前语境明确在找书时，才显示添加书籍。
- 不使用底部大悬浮条样式，避免明显借鉴竞品。
- 搜到部分结果时，不显示“没有搜索到”类文案。

用户场景：

用户搜索《新书名》，本地没有任何内容。页面提示没有找到内容。用户切到书籍或选择添加入口后，可以去添加书籍。

验收标准：

- 有任何结果时不出现全局无结果提示。
- 非书籍语境不主动引导添加书。
- 添加书籍入口不遮挡搜索框和列表。

### 4.11 搜索详情闭环

设计方案：

- 从搜索进入详情后，返回语义是“回到搜索结果”，不是普通根页面返回。
- 详情页展示命中词上下文。
- 书摘详情自动定位到命中段落。
- 多个命中时，后续可提供轻量上/下一个命中入口。
- 返回后保留搜索词、一级分类、二级范围和滚动位置。

用户场景：

用户在书摘结果中点进某条“母亲”的摘录，看完后返回，仍停留在刚才的搜索结果位置，不需要重新输入和重新筛选。

验收标准：

- 返回后搜索上下文不丢失。
- 详情页不出现“高亮能力预留”这类内部实现文案。
- 详情页不和底部搜索框/工具栏重叠。

### 4.12 排序与结果优先级

设计方案：

不引入复杂搜索算法，先用现有命中数据做轻量排序：

- 书籍：书名命中优先，其次作者、译者、出版社、ISBN，再按最近阅读/更新时间。
- 书摘：正文完整命中优先，其次想法命中，再按创建时间或最近更新。
- 相关：标题命中优先，其次内容命中。
- 书评：标题命中优先，其次正文命中。
- 标签命中可作为范围筛选和排序加权，但不强行置顶所有标签结果。

用户场景：

用户搜索“百年孤独”，书名完全匹配的书应排在作者或正文提到“百年孤独”的结果前面。

验收标准：

- 精确命中优先于弱相关命中。
- 同类结果排序稳定，不因快速输入频繁跳动。
- 不展示排序理由给用户。

## 5. 原创性与竞品差异要求

为避免明显抄袭，必须遵守：

- 不采用竞品暗色主题作为搜索主视觉。
- 不复制竞品蓝色大胶囊分类样式。
- 不复制 `正文 851 / 心得 8` 作为主标题表达。
- 不复制底部“没有搜索到，添加新书”的悬浮条样式。
- 不复制每条结果右侧常驻分享和更多按钮。
- 不复制竞品的字段分组位置和视觉比例。

可以借鉴的底层产品逻辑：

- 字段级筛选提升效率。
- 高亮要足够明显。
- 书籍结果要体现阅读状态和来源。
- 结果列表要让用户快速判断内容上下文。

## 6. 指标与验收

核心指标：

- 搜索后点击结果率提升。
- 搜索后 10 秒内点击结果的比例提升。
- 搜索无结果率下降。
- 搜索后清空重搜比例下降。
- 从详情返回后继续浏览搜索结果的比例提升。

体验验收：

- 搜索根页轻、干净，不像说明页。
- 搜索结果页没有调试感文案。
- 单字搜索不压垮首屏。
- 用户能在书籍结果里看到阅读状态和来源。
- 用户能在书摘结果里快速判断正文、想法、所属书籍和时间。

## 7. 分阶段建议

### P0：必须优先完成

- 一级分类稳定：书籍、书摘、相关、书评。
- 结果卡片字段完整、无调试文案。
- 中文组合态、debounce、延迟 loading。
- 搜索上下文返回保留。
- 无结果态和添加书籍入口不冲突。

### P1：提升搜索效率

- 分类内二级范围筛选。
- 书籍结果增加阅读状态、来源、进度、最近阅读。
- 摘要截取优化，高亮增强。
- 分类和范围切换保留滚动位置。

### P2：体验增强

- 多命中上/下一个。
- 搜索历史管理。
- 搜索建议：最近读过、最近摘录过、常用标签。
- 搜索结果页支持更丰富的阅读记录上下文。

## 8. Assumptions

- XMNote 的全局搜索以本地内容为主，不做云端搜索。
- Android 当前四类搜索能力继续作为业务对齐底座。
- 本次产品方案不要求复制竞品视觉，只吸收效率逻辑。
- iOS 继续使用系统 Search Tab 和原生搜索输入体验。
- 复杂排序算法暂不引入，先用命中字段和时间做轻量排序。
