# 搜索交互升级 iOS26 - 需求文档

## 1. 背景
- 当前搜索 Tab 点击后会直接进入 `SearchView`。
- 目标是对齐 iOS 26 原生搜索体验：先在底部触发系统搜索框，开始输入后再进入搜索页面。

## 2. 目标
- 点击底部“搜索”按钮时，仅触发系统底部搜索框。
- 用户开始输入后，自动进入现有搜索 Tab 内容页面。
- 搜索页不再保留自定义顶部搜索栏和页面内手写输入框，避免双重入口。
- 搜索历史在空查询态可浏览、选择、单删和清空，并在编辑态保持稳定的 chip 布局与符合直觉的删除操作槽动效。
- 点击“清空”搜索历史时，先稳定搜索上下文，再展示确认弹窗；确认前不得清空历史、退出编辑态或让底层列表可见重排。

## 3. 范围
- 范围内：
  - `MainTabView` 的搜索 Tab 激活行为改造。
  - `SearchView` 从“输入页”改为“结果承载页”。
  - 全局搜索最近搜索词展示、管理和清空确认。
  - 搜索历史公共组件在全局搜索、书籍搜索与 Debug 场景中的视觉交互一致性。
- 范围外：
  - 网络搜索推荐词。
  - 搜索结果 AI 排序策略。

## 4. 验收标准
- 点“搜索”Tab 后不直接进入搜索页。
- 输入文本后自动打开搜索页。
- 搜索页不存在重复搜索输入 UI。
- 搜索页的书籍/笔记详情导航能力保持不变。
- 历史 chip 进入/退出编辑态时，右侧删除按钮表现为操作槽展开/收起，不出现整组淡出或宽度突变。
- 点击“清空”后弹窗背后只允许系统 dim；历史 chip 数量、编辑态按钮和页面位置在确认前保持不变。
- 点击“取消”后仍保持编辑态；点击 destructive“清空”后才清空历史并退出编辑态。
