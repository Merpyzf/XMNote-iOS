# AI Bug 经验闭环需求文档

## 1. 背景

iOS 仓库已有大量 `fix` 提交、踩坑记录、复盘和静态脚本，但缺少统一案例 ID、根因机制、owner/写入点/生命周期字段、模式准入和检索评测。AI 在处理新缺陷时无法稳定复用这些证据，也容易把视觉调整或一次性修改误收为 Bug 经验。

Android 仓库已有 Markdown/Front Matter、SQLite 索引、Skill、Hook 和 Git gate 原型。iOS 接入必须保留其可审阅、可重建和分层治理优点，同时适配本仓库文档冻结、Apple 平台事实和抽象准入规则。

## 2. 目标

- 修复真实生产缺陷前自动检索相关案例、规则、学习资料和 Git 证据。
- 开发期只在被忽略的 worktree 本地目录维护草稿。
- 用户明确完成后才发布正式案例并执行知识闸门。
- 只有多个独立案例证明同根因、同修复策略后才允许候选模式。
- 不让 App 构建、运行时、业务数据库或网络服务依赖问题库。

## 3. 收集边界

收集：

- 可复现或有明确人工观察路径。
- 能确认真实 owner、写入点和触发时机。
- 已确认根因机制。
- 有验证结果，或明确无法自动化原因。

不收集：

- 纯视觉微调、重构、功能增强、泛化优化。
- 只有修改动作、没有根因机制的提交。
- 仅因提交主题使用 `fix` 的变更。

## 4. 功能需求

1. 标准库 CLI：search、draft、case、pattern、validate、audit、eval、metrics、hook。
2. 本地状态：索引、会话、草稿、指标均位于 `artifacts/ai-knowledge/`。
3. 正式知识：案例、模式、归档及问题库说明位于 `docs/knowledge/bugs/`。
4. Codex：仓库 Skill 指导诊断顺序；Hook 建立基线、首次检索和 Stop 闭环检查。
5. Git：30 天 warning 试运行，格式错误失败关闭，缺案例 trailer 不阻断。
6. 检索：无真实命中的模式不能仅靠权重进入结果。
7. 模式：至少两个独立案例、同根因指纹、同修复策略指纹；active/enforced 分别要求批准和必执行保护。
8. 评测：每个种子两条正例改写和一条边界负例，Recall@5 不低于 80%。

## 5. 非功能需求

- Python 标准库实现；无 Embedding、外部向量库和在线服务。
- 主 worktree 与 Parallel iOS worktree 状态天然隔离。
- 当前已有脏文件作为任务基线，不自动归入新任务。
- Stop 必须防止无限续跑。
- Hook 需要用户信任，且不被描述为完整安全边界。

## 6. 验收结果

- 8 个历史种子完成事实闭环并通过 validate/audit。
- 24 条固定查询达到 Recall@5 100%、MRR 0.9688、负例误召回率 0%。
- 14 个独立工具测试通过。
- 当前 worktree 已配置 `.githooks`；未新增 Xcode Build Phase。
- 未修改 App 业务代码，未新增或运行 App XCTest/UI Test。
