# iOS 阅读计时产品设计文档 v1.0

## 1. 背景与产品目标

阅读计时的核心价值不是“打开一个秒表”，而是帮助用户在纸质阅读场景中完成一次可被沉淀、可被回顾、可进入统计的阅读记录。Android 端已经具备完整的计时、补录、保存和统计消费链路；iOS 端需要对齐这条业务闭环，但不能直接照搬 Android 前台服务、通知栏和功能密集型计时页的交互模型。

iOS 首版目标：

- 从一本书开始阅读，完成开始、暂停、继续、结束、保存记录的闭环。
- 支持事后补录阅读，尤其是“日期 + 时长”的低负担补录。
- 保存后进入现有在读首页、阅读日历、时间线和书架阅读时长统计。
- 支持阅读位置、本次感悟、标记读完等 Android 已有核心补充信息。
- 使用 Live Activity / 灵动岛作为状态补充，而不是把它设计成主流程入口。

iOS 首版不做：

- 白噪音、背景图、环境陪伴。
- OCR 快捷入口和完整相关内容创建入口。
- 倒计时主流程。
- 完整阅读历史管理页。
- Android 通知栏服务模型的一比一迁移。

## 3. Android 端能力 Review

Android 当前已经具备以下能力：

- 入口：书籍详情页可进入阅读计时、阅读补录和阅读记录历史。
- 实时计时：支持正计时、倒计时、暂停、继续、停止。
- 后台维持：通过前台服务与通知栏操作维持计时，通知栏可暂停、继续、结束。
- 异常恢复：运行中或暂停中的记录会被持久化，冷启动时可恢复或放弃。
- 结束确认：停止后进入记录页，补齐开始时间、结束时间、阅读时长、阅读位置、感悟和是否读完。
- 补录：支持精确开始/结束时间，也支持模糊阅读日期 + 阅读时长。
- 数据口径：状态值为 `RUNNING=0 / PAUSE=1 / STOP=2 / FINISHED=3`；只有完成记录进入统计。
- 统计消费：已完成、未删除、有效书籍的阅读记录进入首页阅读时长、阅读日历、时间线和书架总时长。
- 附加体验：白噪音、背景图、OCR 创建书摘、相关内容创建、倒计时结束通知。

Android 端值得保留的业务意图：

- 阅读中的时间不可因切后台或页面返回而丢失。
- 暂停时间需要被排除在实际阅读时长外。
- 停止计时不等于保存记录，用户仍需要确认和补充信息。
- 补录不强迫用户回忆精确起止时间。
- 阅读记录保存后必须进入统一统计口径，而不是独立沉淀在计时页。

## 4. iOS 端对齐范围与首版边界

iOS 必须对齐：

- 从指定书籍开始阅读。
- 实时正计时。
- 暂停、继续、结束。
- 结束后确认保存。
- 放弃未保存记录。
- 补录阅读记录。
- 阅读位置、感悟、标记读完。
- 超过 8 小时的异常时长确认。
- App 重启后恢复未完成计时或允许放弃。
- 保存后进入现有统计、日历、时间线和书籍阅读时长。

iOS 有意差异：

- 入口命名使用“开始阅读”，弱化工具感强的“阅读计时”。
- 结束确认使用底部 Sheet，不使用 Android 式整页强表单。
- 补录默认采用“按日期记录”，而不是默认让用户填写精确起止时间。
- 灵动岛只展示状态和轻操作，不承担核心教育和完整表单任务。
- 白噪音、背景图、OCR、倒计时不进入首版主路径。

## 5. Android 体验问题与 iOS 优化方向

### 5.1 计时页功能过密

Android 计时页同时承担计时、倒计时、白噪音、背景图、OCR、书摘创建、相关内容创建等任务。它更像“阅读陪伴驾驶舱”，但首屏焦点容易从阅读时长本身被稀释。

iOS 优化：

- 计时页只保留书籍、时间、开始/暂停/继续、结束和轻量书摘入口。
- 倒计时与陪伴类能力后置，不作为首版阻塞项。
- 视觉焦点给书封、书名和主计时数字，不在首屏堆叠多组工具。

### 5.2 停止后的保存负担偏重

Android 停止后进入记录页，开始时间、结束时间、时长、位置、感悟、读完状态同权展示。对刚结束阅读的用户来说，表单感强，保存压力偏大。

iOS 优化：

- 停止后弹出底部 Sheet，第一屏先展示“本次时长、书籍、时间范围、保存记录”。
- 阅读位置默认露出，因为它和纸质书场景关系最强。
- 感悟和读完状态保留，但视觉层级低于保存主操作。
- 精确时间编辑收起到“调整时间”入口，避免默认打断。

### 5.3 Android 后台模型不能直接迁移

Android 的稳定性依赖前台服务和通知栏操作。iOS 没有同等常驻服务模型，强行照搬会造成平台预期错位。

iOS 优化：

- App 内主流程保证完整可用。
- 后台状态通过时间戳和累计暂停时长恢复，而不是依赖持续后台 tick。
- Live Activity 展示状态，回到 App 后由本地记录校准当前时长。
- 不承诺 iOS 后台持续执行计时逻辑，只承诺计时结果不倒退、不丢失。

## 6. iOS 阅读计时入口设计

### 6.1 书籍详情页入口

主入口放在书籍详情页顶部操作区，命名为“开始阅读”。

设计理由：

- 用户在书籍详情页已经明确选择了书，适合开始一次阅读。
- “开始阅读”表达的是用户意图，“阅读计时”表达的是工具能力。
- 主按钮应服务开始阅读，不被补录、历史、设置等功能分散。

同页次级入口：

- “补录阅读”放在更多菜单或阅读数据区。
- “阅读记录历史”不进入首版主入口，可后续在阅读数据区补齐。

### 6.2 在读首页入口

在读首页“继续阅读”卡增加开始计时能力。

规则：

- 有最近在读书：点击主区域进入该书详情；卡片内或长按/次级按钮可“开始阅读”。
- 无最近在读书：入口引导选择一本书或添加书籍。
- 不把首页改造成计时大入口，避免破坏首页概览属性。

### 6.3 补录入口

入口统一命名为“补录阅读”。

推荐出现位置：

- 书籍详情页更多菜单。
- 书籍详情页阅读数据区。
- 后续可在阅读日历空日或时间线空态中加入补录入口。

## 7. 实时阅读计时主流程

### 7.1 进入计时页

用户点击“开始阅读”后进入全屏计时页。

首屏信息：

- 书封。
- 书名。
- 作者。
- 主计时数字。
- 当前状态：未开始、计时中、已暂停。
- 主操作按钮。
- 次操作“结束”。
- 轻量入口“记书摘”。

页面原则：

- 主屏不放表单。
- 主操作只有一个，根据状态变化为“开始 / 暂停 / 继续”。
- “结束”保持次级但可见，不隐藏到更多菜单。
- 计时数字使用稳定等宽数字，避免跳秒造成布局抖动。

### 7.2 开始

点击“开始”：

- 创建一条进行中的计时记录。
- 记录开始时间。
- 状态进入 `running`。
- 主按钮变为“暂停”。
- 如设备支持，创建 Live Activity。

产品反馈：

- 按钮即时进入计时中状态。
- 计时数字从 `00:00:00` 开始递增。
- 不弹出额外说明。

### 7.3 暂停

点击“暂停”：

- 状态进入 `paused`。
- 计时数字停止跳动。
- 累计暂停开始时间。
- 主按钮变为“继续”。
- Live Activity 显示“已暂停 · HH:MM”。

产品原则：

- 暂停不是结束，不展示保存表单。
- 暂停中的页面仍允许“结束”。
- 暂停时不在灵动岛持续跳秒，避免制造“仍在计时”的错觉。

### 7.4 继续

点击“继续”：

- 状态回到 `running`。
- 暂停区间计入累计暂停时长。
- 主按钮变为“暂停”。
- Live Activity 恢复展示当前阅读时长。

产品原则：

- 继续后时长不应包含暂停区间。
- 页面不需要解释计算规则，结果自然准确即可。

### 7.5 记书摘

计时页保留轻量“记书摘”入口。

规则：

- 点击后进入现有书摘创建流程，并预选当前书籍。
- 返回计时页后保持原计时状态。
- 首版不提供 OCR 快捷入口；OCR 属于后续效率扩展，不进入计时核心闭环。

## 8. 结束、保存与放弃流程

### 8.1 点击结束

点击“结束”后：

- 计时状态进入 `stoppedPendingSave`。
- 停止主计时。
- 弹出底部结束确认 Sheet。
- Live Activity 更新为“待保存”。

不允许：

- 点击结束后静默保存。
- 点击结束后直接丢弃记录。
- 结束后仍让灵动岛显示“计时中”。

### 8.2 结束确认 Sheet

Sheet 第一屏展示：

- 本次阅读时长。
- 书籍名称。
- 起止时间。
- 阅读位置输入。
- 本次感悟输入。
- 标记读完 Toggle。
- 主按钮“保存记录”。
- 次按钮“放弃本次”。

层级规则：

- 时长是第一信息。
- 阅读位置默认露出。
- 感悟支持多行输入，但不强制填写。
- 标记读完是显式 Toggle，不默认代替用户判断。
- 调整开始/结束时间收起到次级入口。

### 8.3 保存

点击“保存记录”：

- 校验阅读位置是否符合书籍进度单位。
- 如果时长超过 8 小时，先展示确认弹窗：`这次阅读记录为 X 小时，是否保存？`
- 用户确认后写入完成记录。
- 记录状态进入 `finished`。
- 结束 Live Activity。
- 返回书籍详情页或在读首页，并刷新统计。

保存后应影响：

- 在读首页今日阅读时长。
- 阅读日历当天事件。
- 时间线阅读计时事件。
- 书架和书籍详情中的累计阅读时长。
- 如勾选读完，同步书籍阅读状态。

### 8.4 放弃

点击“放弃本次”：

- 二次确认：`放弃后本次计时不会进入统计。`
- 确认后结束 Live Activity。
- 未完成记录不进入 finished 统计。

规则：

- 如果已有运行中记录，可软删除或标记为 discarded/deleted。
- 不允许放弃后留下可被统计消费的半成品记录。

### 8.5 未保存退出保护

触发场景：

- 计时中返回。
- 暂停中返回。
- 已结束但未保存时关闭 Sheet 或返回。
- App 被系统终止后再次打开。

交互规则：

- 运行中或暂停中返回：提示“继续计时 / 放弃本次”。
- 已结束待保存：提示“保存记录 / 放弃本次”。
- 冷启动恢复：展示未完成阅读卡，允许“继续阅读 / 保存记录 / 放弃本次”。

## 9. 补录阅读流程

### 9.1 默认模式

补录默认进入“按日期记录”。

默认字段：

- 书籍。
- 阅读日期。
- 阅读时长。
- 阅读位置。
- 本次感悟。
- 标记读完。

设计理由：

- 用户补录通常只记得“哪天读了多久”，不一定记得精确起止时间。
- “按日期记录”比“模糊时间”更符合用户语言。
- 日期 + 时长足以进入阅读日历和时间线。

### 9.2 精确模式

提供模式切换：“按开始结束记录”。

字段：

- 开始时间。
- 结束时间。
- 自动计算阅读时长。
- 阅读位置。
- 本次感悟。
- 标记读完。

规则：

- 结束时间不能晚于当前时间。
- 开始时间必须早于结束时间。
- 自动计算出的时长为保存口径。
- 超过 8 小时同样触发确认。

### 9.3 模式文案

不使用：

- 模糊时间。
- 精确时间。
- 不精确记录。

使用：

- 按日期记录。
- 按开始结束记录。
- 阅读日期。
- 阅读时长。

## 10. 灵动岛与 Live Activity 产品规则

Live Activity 的定位是“正在阅读的状态延伸”，不是阅读计时的主入口。

### 10.1 触发条件

- 仅当用户明确点击“开始”后创建。
- 进入计时页但未开始时不创建。
- 补录阅读不创建。
- 用户放弃或保存后立即结束。

### 10.2 紧凑态

展示：

- 左侧：书本或计时图标。
- 右侧：当前时长，暂停时显示暂停符号或“暂停”短标识。

规则：

- 不展示书名，避免拥挤。
- 不展示多个操作按钮。

### 10.3 展开态

展示：

- 书名。
- 当前时长。
- 状态：计时中 / 已暂停 / 待保存。
- 操作：暂停或继续、结束。
- 点击主体回到计时页。

规则：

- 操作只覆盖高频轻动作。
- 不在灵动岛内编辑阅读位置、感悟或读完状态。
- 结束后如果仍待保存，点击回到结束确认 Sheet。

### 10.4 锁屏态

展示：

- 书名。
- 当前阅读时长。
- 开始时间。
- 暂停状态。
- 结束入口。

规则：

- 暂停时不持续跳秒。
- 待保存时展示“待保存”，避免用户误以为已入库。

### 10.5 设备退化

- 不支持灵动岛的设备展示锁屏 Live Activity。
- 用户关闭 Live Activities 权限时，不影响 App 内计时主流程。
- Live Activity 失败不应阻断开始阅读。

## 11. 数据口径与统计消费规则

### 11.1 产品状态

iOS 产品层使用以下状态：

| 状态 | 含义 | 是否进入统计 |
| --- | --- | --- |
| `running` | 计时中 | 否 |
| `paused` | 暂停中 | 否 |
| `stoppedPendingSave` | 已结束，等待保存 | 否 |
| `finished` | 已保存完成 | 是 |
| `discarded/deleted` | 用户放弃或删除 | 否 |

### 11.2 与 Android 状态对齐

Android 数据状态：

| Android 状态 | 值 | iOS 产品语义 |
| --- | --- | --- |
| `RUNNING` | 0 | `running` |
| `PAUSE` | 1 | `paused` |
| `STOP` | 2 | `stoppedPendingSave` |
| `FINISHED` | 3 | `finished` |

### 11.3 字段口径

实时计时：

- `book_id`：当前书籍。
- `start_time`：开始时间，毫秒时间戳。
- `end_time`：结束时间，毫秒时间戳。
- `elapsed_seconds`：实际阅读秒数，不包含暂停时间。
- `paused_duration_millis`：累计暂停毫秒数。
- `paused`：当前是否暂停。
- `status`：运行、暂停、停止待保存或已完成。

结束补充：

- `position`：阅读位置。
- `recorded_position_unit`：记录当次位置单位快照。
- `insight`：本次感悟。

补录：

- 按日期记录：写入 `fuzzy_read_date` 与 `elapsed_seconds`。
- 按开始结束记录：写入 `start_time`、`end_time` 与 `elapsed_seconds`。

### 11.4 统计消费

统计只消费：

- `status = 3`。
- `is_deleted = 0`。
- `book_id != 0`。
- `elapsed_seconds > 0` 的有效记录。

日期归属：

- 如果 `fuzzy_read_date != 0`，按 `fuzzy_read_date` 归属。
- 如果 `fuzzy_read_date = 0`，按 `start_time` 或精确区间归属。
- 跨天精确记录在统计层按既有规则拆分。

## 12. 异常与边界

### 12.1 App 进入后台

预期：

- Live Activity / 锁屏继续展示状态。
- 回到 App 后按开始时间、暂停累计和当前时间重新计算。
- 计时结果不倒退。

### 12.2 App 被杀进程

再次打开：

- 如果存在 `running` 或 `paused` 记录，展示恢复入口。
- 用户可以继续阅读或放弃本次。
- 如果存在 `stoppedPendingSave`，优先回到待保存确认。

### 12.3 系统时间变化

预期：

- 进入前台时校准当前时长。
- 发现结束时间早于开始时间、或明显异常时，进入人工确认而非静默保存。

### 12.4 多设备与同步

首版不设计跨设备同时计时冲突解决。阅读计时以当前设备本地记录为主，完成后进入既有备份和同步链路。

## 13. 关键页面文案

入口：

- `开始阅读`
- `补录阅读`

计时页：

- `开始`
- `暂停`
- `继续`
- `结束`
- `记书摘`

结束确认：

- `保存记录`
- `放弃本次`
- `这次阅读记录为 X 小时，是否保存？`
- `放弃后本次计时不会进入统计。`

补录：

- `按日期记录`
- `按开始结束记录`
- `阅读日期`
- `阅读时长`

- `发现一条未完成的阅读计时`
- `继续阅读`
- `保存记录`
- `放弃本次`

## 14. 验收标准

- 从书籍详情页点击“开始阅读”，可以开始、暂停、继续、结束并保存。
- 保存后，在读首页今日时长、阅读日历、时间线和书架累计阅读时长同步变化。
- 计时暂停期间不计入实际阅读时长。
- 点击结束后不会直接保存，必须进入确认 Sheet。
- 未保存退出时必须给出保存或放弃选择。
- 超过 8 小时保存前必须二次确认。
- 补录“按日期记录”后，记录归属到所选日期，并进入阅读日历和时间线。
- 补录“按开始结束记录”后，自动计算时长，并按精确时间进入统计。
- App 进入后台后，Live Activity 或锁屏状态可以展示当前阅读状态；回到 App 后时长不倒退。
- App 被杀进程后再次打开，可恢复未完成计时或放弃本次记录。
- 不支持 Live Activity 或权限关闭时，App 内主流程仍完整可用。

## 15. 后续版本

后续可评估：

- 阅读目标时长与倒计时。
- 白噪音和专注陪伴。
- 计时页快捷 OCR / 书摘创建增强。
- 阅读记录历史管理。
- 阅读日历空日补录入口。
- 基于 Live Activity 的更丰富锁屏样式。

后续扩展原则：

- 不牺牲“开始阅读 - 保存记录”的核心闭环。
- 陪伴能力只能作为可选增强，不进入首版主路径。
- 所有新增记录仍必须落入统一 `read_time_record` 统计口径。
