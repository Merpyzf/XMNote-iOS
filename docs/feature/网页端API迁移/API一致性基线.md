## 合同口径

- 全部接口以 `endpoint-manifest.json` 为机器可读清单，Todo 为人工审查视图。
- 普通 JSON 接口同时对比 HTTP 状态、Header、`code`、`msg`、`data` 类型和值。
- 不通过重排数组、删除 `null`、宽松数字类型或全局忽略时间字段掩盖差异。
- 时间、设备路径、临时文件名等只有在接口合同本身不承诺精确值时，才可按字段制定明确的归一化规则。
- 变更接口除响应外，必须对比数据库行、软删除状态、级联影响、排序值、时间戳和必要的设置副作用。
- 二进制、下载、Range 和 SSE 接口按字节、媒体类型、Content-Disposition、分块/终止行为分别对比。
- Android 已确认异常也是本次基线的可观察行为：iOS 先 1:1 复刻，同时在代码和 `Android API Review问题.md` 标记 TODO，不在本任务静默修正。

| 状态 | 含义 |
| --- | --- |
| `pending` | 尚未完成双端对比 |
| `exact` | 状态、Header、响应体与副作用精确一致 |
| `normalized` | 仅按已记录的字段级规则归一化后一致 |
| `protocol` | 流式/二进制协议行为一致，业务载荷由外部系统决定 |
| `blocked` | 因外部账号、网络或系统能力无法完成，必须记录证据和解锁条件 |
