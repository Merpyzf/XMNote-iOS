# AI 辅助 - 设计文档

## 1. 架构

- 模型：`xmnote/Domain/Models/AIModels.swift`
- 契约：`AIRepositoryProtocol`
- Repository：`xmnote/Data/Repositories/AIRepository.swift`
- 网络：`xmnote/Infra/AI/OpenAICompatibleClient.swift`
- 本地配置：`AIConfigurationStore` 的 `ai.configuration.v2` 原子 UserDefaults 快照
- 备份白名单：`IOSUserDefaultsBackupCoordinator` + `IOSPreferencesBackupEnvelope`
- UI：`ContentViewer` 选区菜单、`AIInteractionSheets`、AI 设置页

## 2. 数据流

```text
用户操作 -> ViewModel -> AIRepository
  -> 读取完整本机配置快照
  -> OpenAI-compatible 流式/非流式请求
  -> 用户确认
  -> Repository 数据库事务
```

## 3. 一致性保护

- 书摘解读保存时在同一事务重新读取最新 idea，再追加 AI HTML 块。
- 自动标签复用 Note Repository 的标签事务，不复制数据写入逻辑。
- `AsyncThrowingStream` 的生产任务响应取消，网络状态不直接成为 View 的 owner。
- Provider/模型/Prompt 在 Repository 入口统一校验。
- `AIConfigurationStore` 首次读取 v2 不存在时，合并 v1 配置与两家旧 Keychain 凭据；v2 写入成功后清理旧存储，后续不再回读旧凭据。
- 本地、WebDAV 与阿里云备份共用 `BackupRepository.createArchiveArtifact`，由白名单协调器生成 iOS sidecar，避免各云端实现自行挑选偏好字段。
- 恢复必须先完成数据库 staging 校验、替换与重开，再整组应用有效 AI 快照；sidecar 缺失保留当前设置，损坏或高版本只降级为部分恢复。
- sidecar 结构、1 MiB 限制、敏感字段边界与扩展准入以 `docs/architecture/数据备份机制设计.md` 为准。

## 4. 平台表达

- iOS 使用系统文本选区菜单和 Sheet；Android 使用 TextView ActionMode 与 Compose/BottomSheet。
- 交互不同但 Prompt、供应商、错误分类和最终写入语义对齐。
- `xmnote_ios_preferences.json` 是 iOS 设备间恢复的可选附加层；Android 无需读取，数据库仍是跨端共享事实源。
