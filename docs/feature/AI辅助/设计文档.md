# AI 辅助 - 设计文档

## 1. 架构

- 模型：`xmnote/Domain/Models/AIModels.swift`、`xmnote/Domain/Models/AIPromptEditingModels.swift`
- 契约：`AIRepositoryProtocol`
- Repository：`xmnote/Data/Repositories/AIRepository.swift`，统一正式请求、离线预览、试运行和字段优化的数据边界
- 网络：`xmnote/Infra/AI/OpenAICompatibleClient.swift`
- 本地配置：`AIConfigurationStore` 的 `ai.configuration.v2` 原子 UserDefaults 快照，以及单任务 Prompt 的 Actor 隔离替换
- 备份白名单：`IOSUserDefaultsBackupCoordinator` + `IOSPreferencesBackupEnvelope`
- 状态：`AIConfigurationViewModel` 管理配置页快照，`AIPromptEditorViewModel` 独立管理单任务双字段草稿和派生结果
- UI：`ContentViewer` 选区菜单、`AIInteractionSheets`、AI 设置页、`AIPromptEditorView`、页面私有 TextKit 令牌编辑器及业务 Sheet

## 2. 数据流

```text
用户操作 -> ViewModel -> AIRepository
  -> 读取完整本机配置快照
  -> OpenAI-compatible 流式/非流式请求
  -> 用户确认
  -> Repository 数据库事务
```

提示词编辑链路：

```text
AI 配置页 -> PersonalRoute.aiPromptEditor(kind)
  -> AIPromptEditorViewModel 读取当前任务 Prompt
  -> AIPromptValidator 实时派生问题
  -> AIPromptRequestBuilder 统一变量替换与应用固定协议
  -> AIRepository 预览 / 试运行 / 优化
  -> AIConfigurationStore 只替换当前任务 Prompt 并原子写回 v2 快照
```

## 3. 一致性保护

- 书摘解读保存时在同一事务重新读取最新 idea，再追加 AI HTML 块。
- 自动标签复用 Note Repository 的标签事务，不复制数据写入逻辑。
- `AsyncThrowingStream` 的生产任务响应取消，网络状态不直接成为 View 的 owner。
- Provider/模型/Prompt 在 Repository 入口统一校验。
- `AIPromptVariableCatalog` 是三类任务变量的唯一白名单；TextKit 编辑器只负责令牌视觉、选区和撤销，原始字符串始终保留 `${变量名}`。
- `AIPromptValidator` 同时服务页面提示、保存和请求前校验；ViewModel 的派生状态不能替代 Repository 的最终防线。
- `AIPromptRequestBuilder` 是预览、试运行和正式请求的唯一消息构建入口，避免编辑页看到的内容与线上实际发送内容分叉。
- 保存锁定发起时的双字段快照；保存期间的新输入继续保持 dirty，只有页面草稿仍等于已保存快照时才允许退出。
- 试运行和优化由 Sheet 持有结构化 Task，ViewModel 同时绑定 request ID 与草稿快照；取消、字段切换或文本变化后拒绝旧响应。
- `navigationPopGuard` 只在存在脏草稿或写入中阻断返回，交互式返回取消后恢复原编辑焦点。
- `AIConfigurationStore` 首次读取 v2 不存在时，合并 v1 配置与两家旧 Keychain 凭据；v2 写入成功后清理旧存储，后续不再回读旧凭据。
- 本地、WebDAV 与阿里云备份共用 `BackupRepository.createArchiveArtifact`，由白名单协调器生成 iOS sidecar，避免各云端实现自行挑选偏好字段。
- 恢复必须先完成数据库 staging 校验、替换与重开，再整组应用有效 AI 快照；sidecar 缺失保留当前设置，损坏或高版本只降级为部分恢复。
- sidecar 结构、1 MiB 限制、敏感字段边界与扩展准入以 `docs/architecture/数据备份机制设计.md` 为准。

## 4. 平台表达

- iOS 使用系统文本选区菜单和 Sheet；Android 使用 TextView ActionMode 与 Compose/BottomSheet。
- Android 的 `PromptEditActivity` 使用双页 Pager 与 `MarkedTextField`；iOS 使用独立 push 页面、分段字段切换和 TextKit 原子令牌，业务字段、变量名称、恢复与未保存退出语义对齐。
- iOS 在 Android 基础能力上增加阻断校验、正式请求预览、显式试运行/默认对照和字段优化；这些属于可回退的产品增强，不改变跨端数据库合同。
- `xmnote_ios_preferences.json` 是 iOS 设备间恢复的可选附加层；Android 无需读取，数据库仍是跨端共享事实源。
