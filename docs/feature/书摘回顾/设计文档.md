# 书摘回顾 - 设计文档

## 1. 架构目标
- 让 iOS 回顾页对齐 Android 的业务意图：范围筛选、随机/顺序回顾、卡片堆叠浏览、设置变更刷新。
- 保持 iOS 分层边界：View 只承载渲染与交互，ViewModel 编排状态，Repository 负责本地数据查询。
- 把卡组动效收敛到可测试的纯模型，避免 SwiftUI 视图层出现难以复现的层级和透明度问题。

## 2. 分层设计

### 2.1 View
- `NoteContainerView`
  - 托管“笔记 / 回顾”二级切换。
  - 负责顶部设置入口与 `NoteReviewSettingsSheet` 展示。
- `NoteReviewView`
  - 承载加载态、空态、`NoteReviewPagingDeck`、辅助刷新行和 context menu。
  - 点击卡片进入内容查看器；长操作通过 context menu 承接。
- `NoteReviewCardView`
  - 页面私有卡片内容视图。
  - 渲染正文、想法、附图、标签、footer 书籍信息。
  - footer 只保留分割线，不再绘制横向 wash 背景。

### 2.2 ViewModel
- `NoteReviewViewModel`
  - 首次加载设置、标签、已选书籍和第一页卡片。
  - 编排刷新、分页、设置保存、标签编辑、分享图生成与外部应用发送反馈。
  - 使用 generation token 避免旧异步任务回写新状态。

### 2.3 Domain / Data
- `NoteReviewModels`
  - 定义 `NoteReviewSettings`、`NoteReviewCardItem`、排序规则、标签匹配规则、配色和文本对齐。
- `NoteRepository`
  - 通过 `fetchNoteReviewPage(request:)` 按设置读取卡片页。
  - 随机模式使用 `ORDER BY RANDOM()` 并排除已展示 note id。
  - 顺序模式按 Android 语义使用 `book_id DESC, note.id ASC`，通过 `LIMIT/OFFSET` 分页。
- `NoteReviewSettingStore`
  - 负责回顾设置本地存储与变更广播。

### 2.4 UIComponents
- `NoteReviewPagingDeck`
  - 包装 BigUIPaging `PageView`，对外暴露稳定的 item/selection 接口。
  - 负责双向手势、后卡补位、分页预加载和可访问性隐藏。
- `NoteReviewPagingMotionSpec`
  - 纯动效模型，集中计算卡片位置、缩放、旋转、内容可见性、zIndex 与堆叠露出约束。
  - 测试覆盖 handoff、commit 边界、next/previous 对称路径和露出安全区。

## 3. 关键交互流

### 3.1 首次进入
1. `NoteReviewView.task` 调用 `viewModel.loadIfNeeded()`。
2. ViewModel 并发读取标签选项、已选书籍和第一页卡片。
3. 成功后将第一页卡片写入 `items`，并同步 `selectedItemID`。

### 3.2 横向切卡
1. `NoteReviewPagingDeck` 将当前 `selection` 转为 `PageView` 页面值。
2. 拖拽开始后 `NoteReviewPagingVisualSession` 记录 source identity 和 sourceIndex。
3. 拖拽过程中 `NoteReviewPagingMotionSpec` 按 progress 连续输出 transform。
4. 达到提交阈值后先把可视进度动画到 commit boundary。
5. 动画完成后再写回外部 selection、更新 selectedIndex、清理 visualSession 并重建 pages。

### 3.3 内容 handoff
- source 卡正文不在 handoff 前突然消失。
- target 卡正文从切换早段开始显现，handoff 附近目标卡不再是空白纸面。
- 后层卡使用 `.preview`：正文与 footer 可见，但不可点击、不可读。

### 3.4 堆叠露出约束
- 后层卡在旋转后计算 AABB：
  - `rotatedW = w * cos(theta) + h * sin(theta)`
  - `rotatedH = w * sin(theta) + h * cos(theta)`
- 侧边露出：
  - `sidePeek = max(0, abs(offsetX) + rotatedW / 2 - cardW / 2)`
- 底部露出：
  - `bottomPeek = max(0, offsetY + rotatedH / 2 - cardH / 2)`
- 若超过限制，先降低旋转角，再 clamp 横向和纵向 offset。
- 允许侧边露出只落在正文安全边距外；底部露出不超过 4pt。

### 3.5 footer 封面
- 屏幕卡片 footer 使用：
  - `XMBookCover.fixedWidth(NoteReviewCardLayout.footerCoverWidth, surfaceStyle: .spine)`
- `footerCoverWidth` 保持 36pt，由 `XMBookCover.size(width:)` 推导全局宽高比。
- 当前 36pt 宽度下 `XMBookCover` 会解析为 plain surface tier；这是为了维持紧凑 footer，不强行放大封面。
- 分享 PNG 继续走 `NoteReviewShareImageRenderer` 的 1240px 离屏渲染，不复用屏幕 footer 布局。

## 4. 关键设计决策
- 不隐藏后层卡内容
  - 原因：竞品动效方向是后卡带内容补到前景；隐藏内容会造成空白纸面和层级 handoff 突变。
- 用几何约束解决露字
  - 原因：需求要求低卡仍绘制文本，正确做法是控制可见露出范围。
- selection 延迟提交
  - 原因：过早提交会触发 pages 重建，使动画尾段跳到新静止态。
- 屏幕卡片与分享图分离
  - 原因：屏幕卡片为交互阅读服务，分享图为固定高分辨率导出，二者尺寸目标不同。

## 5. 验证策略
- 单元测试：
  - `NoteReviewPagingMotionSpecTests`
  - `NoteReviewPagingStateTests`
- 构建验证：
  - `xcodebuild -project xmnote.xcodeproj -scheme xmnote -destination "platform=iOS Simulator,id=${BOOTED_SIMULATOR_ID}" build`
- 人工复查：
  - 前卡退到后层连续。
  - 后层卡露出区域无正文或 footer 文本。
  - footer 无横向深色块。
  - 封面宽高比与 `XMBookCover` 一致。
