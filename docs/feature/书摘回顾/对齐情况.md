# 书摘回顾 - 对齐情况

## 1. 总体结论
- iOS 已完成 Android 书摘回顾的核心业务意图迁移：二级回顾页、范围筛选、随机/顺序读取、卡片堆叠浏览、设置变更刷新、保存分享图与打开微信读书原文。
- iOS 在交互表达上做了原生增强：使用 SwiftUI context menu、Sheet 设置页、可测试的卡组动效模型和 Repository 数据边界。
- 当前有意差异主要集中在视觉表达：iOS 不复刻 Android 的全屏/音量键切卡和图片背景设置，优先保留本项目 iOS 当前 UI 风格。

## 2. 功能点对齐

1. 笔记 Tab 回顾入口
- iOS 行为：`NoteContainerView` 托管“笔记 / 回顾”二级切换，并在回顾页通过顶部设置入口打开设置 Sheet。
- Android 行为：`NoteContainerFragment` 通过 ViewPager 加载 `NoteReviewFragment`，功能按钮在回顾页打开 `NoteReviewSettingActivity`。
- 对齐状态：已对齐。
- 双端代码证据：
  - iOS：`xmnote/Views/Note/NoteContainerView.swift:1`、`xmnote/Views/Note/NoteReviewView.swift:92`
  - Android：`/Users/wangke/Workspace/AndroidProjects/XMNote/app/src/main/java/com/merpyzf/xmnote/ui/main/container/NoteContainerFragment.kt:93`、`/Users/wangke/Workspace/AndroidProjects/XMNote/app/src/main/java/com/merpyzf/xmnote/ui/main/container/NoteContainerFragment.kt:140`

2. 卡片堆叠浏览
- iOS 行为：`NoteReviewPagingDeck` 基于 BigUIPaging 承接左滑下一张、右滑上一张、selection 归一化、预加载与点击详情。
- Android 行为：`NoteReviewFragment` 使用 `CardStackLayoutManager` 和 `NoteCardStackAdapter` 承接堆叠卡片浏览。
- 对齐状态：已对齐。
- 双端代码证据：
  - iOS：`xmnote/Views/Note/Components/NoteReviewPaging/NoteReviewPagingDeck.swift:17`、`xmnote/Views/Note/NoteReviewView.swift:94`

3. 卡片内容展示
- iOS 行为：`NoteReviewCardView` 展示正文、想法、附图、标签、书籍封面、书名与作者；封面统一走 `XMBookCover`。
- Android 行为：`NoteCardStackAdapter` 绑定正文、想法、图片墙和书名。
- 对齐状态：已对齐。
- 双端代码证据：

4. 数据读取与筛选
- iOS 行为：`NoteReviewViewModel` 经 `NoteRepositoryProtocol` 读取设置、标签、已选书籍和分页卡片；`NoteRepository` 按书籍、标签、标签规则和排序规则拼接 GRDB 查询。
- Android 行为：`NoteReviewPresenter` 从 `SpSettingHelper` 读取书籍、标签和排序规则，再调用 data 层 `NoteRepository.getOrderNotes/getRandomNotes`。
- 对齐状态：已对齐。
- 双端代码证据：

5. 设置项
- iOS 行为：`NoteReviewSettingsSheet` 支持书籍范围、标签范围、标签规则、显示顺序、卡片配色和文本对齐。
- Android 行为：`NoteReviewSettingActivity` 支持显示顺序、背景类型、文字颜色、文本对齐、字体、书籍来源、标签来源和标签筛选规则。
- 对齐状态：部分对齐。
- 差异评估：iOS 当前保留核心范围筛选和阅读样式设置，但未迁移图片背景、文字颜色与自定义字体；这属于 iOS 当前设计收敛，不是业务倒退。
- 双端代码证据：
  - iOS：`xmnote/Views/Note/Sheets/NoteReviewSettingsSheet.swift:66`、`xmnote/Views/Note/Sheets/NoteReviewSettingsSheet.swift:97`
  - Android：`/Users/wangke/Workspace/AndroidProjects/XMNote/app/src/main/java/com/merpyzf/xmnote/ui/main/activity/note/NoteReviewSettingActivity.kt:194`、`/Users/wangke/Workspace/AndroidProjects/XMNote/app/src/main/java/com/merpyzf/xmnote/ui/main/activity/note/NoteReviewSettingActivity.kt:216`
- Android 反向建议：
  - 是否吸收：可评估。
  - 建议优先级：中。
  - 建议内容：Android 设置页可考虑把“数据范围”和“视觉样式”分组，降低当前长列表设置的理解成本。

6. 卡片切换动效
- iOS 行为：`NoteReviewPagingMotionSpec` 通过 source support proxy、内容 visibility handoff 和延迟 selection commit 保证动画连续；后层卡内容保持 preview 可见但不可读。
- Android 行为：CardStackView 提供连续堆叠切换，Adapter 负责完整内容绘制。
- 对齐状态：已对齐，并按竞品录屏方向增强。

9. 全屏与音量键切卡
- iOS 行为：当前不提供全屏模式和音量键切卡；保留 iOS Tab/底部导航的当前沉浸边界。
- Android 行为：`NoteContainerFragment` 支持进入全屏；`NoteReviewFragment` 监听音量键触发 rewind/swipe。
- 对齐状态：有意差异。
- 差异评估：属于平台交互差异。iOS 不建议占用硬件音量键作为卡片导航。
- 双端代码证据：

  - 建议优先级：低。

## 3. 结论建议
- iOS 当前已经完成书摘回顾核心功能对齐，并围绕动效连续性、后层卡预览和封面统一组件做了 iOS 原生化优化。
- Android 可考虑吸收“数据范围与视觉样式分组”的设置页组织方式；硬件键和全屏模式不建议作为 iOS 对齐目标。
