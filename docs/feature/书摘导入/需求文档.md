# 书摘导入需求文档

更新日期：2026-09-07

## 目标

将文件、剪贴板、API 与微信读书等来源统一为“候选预览、用户选择、确认写入、结果反馈”的导入流程。用户在落库前必须能够确认目标书、内容范围与阅读时长处理方式；失败或取消不得把未确认的选择写入本地书库。

## 范围

- 为不同来源显示真实可用的来源图标和能力；不以数据模型字段的存在伪造筛选能力。
- 支持书籍搜索、阅读状态、内容数量和阅读时长筛选；“全选”只作用于当前筛选结果。
- 支持逐书指定已有目标书、新建书资料、书摘/书评内容范围与阅读时长合并策略。
- 提交前阻断没有可导入内容或目标书映射仍不明确的书；提交后按结果区分成功、跳过与失败。
- 支持 API 与微信读书来源的候选导入，不将获取候选与实际写库混称为同一动作。

## 非目标

- 不承诺后台自动同步外部平台。
- 不在本次范围改变 Android 导入库的 schema、Room migration 或网络授权协议。
- 不把来源截图、临时生成素材或个人配置提交到仓库。

## 验收口径

1. 候选书只在用户确认提交后进入 Repository 写入路径。
2. 用户改变筛选不会丢失被隐藏的已选书；全选仅影响当前结果。
3. 目标匹配和时长异步补全的迟到结果不会覆盖新的选择。
4. 单书失败保留其他书的成功结果，并在结果页可辨识。
5. 取消、无可选内容、缺少时长等边界状态具有明确反馈，不产生空书或伪造时长。
