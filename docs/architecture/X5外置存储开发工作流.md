### 4.2 为什么 Xcode Locations 仍显示内置路径

Xcode Settings → Locations 显示的是全局 DerivedData 根目录，不解析和展示单个项目子目录的最终符号链接。因此界面仍显示：

```text

```

这不表示 XMNote 仍在内置盘构建。判断迁移是否有效必须检查 XMNote 子目录的 `realpath` 或最终 App 路径，例如：

```bash

```

预期结果必须以 `/Volumes/X5/` 开头。

当前不把 Xcode 全局 DerivedData 根目录改为 X5，原因是全局修改会让所有 Xcode 项目依赖 X5。当前方案只影响 XMNote 主项目，故障范围更小。

Xcode Locations 中的 Archives 和 Compilation Cache 仍显示内置路径也是预期行为：它们按迁移方案继续保留在内置盘。

## 10. 常见问题诊断

### 10.1 Xcode Locations 没显示 X5

这是项目级符号链接方案的预期表现。检查 XMNote 子目录的 `realpath`，不要仅凭 Xcode 全局 Locations 文案判断。

### 10.2 Xcode 又创建了另一个 XMNote DerivedData 目录

可能原因：

- 工程绝对路径发生变化。
- 从另一个 worktree 直接使用普通 Xcode 构建。
- Xcode 版本或工程身份计算变化，DerivedData hash 改变。

处理步骤：

1. 停止当前构建。
2. 使用 `ls -ld /Users/wangke/Library/Developer/Xcode/DerivedData/XMNote-*` 找到新目录。
3. 核对新目录的最近修改时间和真实工程路径。
4. 不要直接删除；先确认它是否属于主项目或某个 worktree。
5. Codex 非主 worktree 应回到 Parallel iOS 工作流，不应共享主项目 DerivedData。

### 10.3 Parallel iOS 报 X5 未挂载或 UUID 错误

先执行：

```bash
diskutil info /Volumes/X5
```

不要让脚本回退到内置路径，不要创建 `/Volumes/X5` 普通目录伪装挂载点，也不要在排障时主动卸载或弹出 X5。只有挂载点和 UUID 都恢复正确后才能继续外置构建。

### 10.4 XcodeBuildMCP profile 为空或路径错误

先运行 `session_show_defaults`。如果不是 `xmnote-x5`，重新加载本地 profile，并再次核对 project、scheme、Simulator 和 DerivedData。不要在默认值为空时直接构建，否则可能在内置盘生成新的 workspace DerivedData。

### 10.5 冷构建耗时较长

- XcodeBuildMCP 首次冷构建可能超过 120 秒。
- 新 Simulator 首次启动的数据迁移可能持续数分钟。
- 等待同一个构建或启动流程完成，不要并发启动第二次构建。
- 不要因为等待时间长而执行 Simulator erase、delete all、CoreSimulator killall 或 X5 卸载操作。

## 11. X5 断开或异常状态

X5 不可用时：

- 主仓库源码浏览、编辑、Git diff、commit 和 branch 操作仍可用。
- 主 Xcode 构建会因为 DerivedData 符号链接目标不可用而失败。
- XcodeBuildMCP 会因为外置 DerivedData 不可用而失败。
- Parallel iOS 会被挂载点和 UUID 保护主动阻止。
- 不允许静默回退到内置盘创建替代缓存。

构建中异常失去 X5 时：

1. 停止当前构建，不继续使用受影响的增量状态。
2. 确认 X5 重新出现在 `/Volumes/X5` 且 UUID 正确。
3. 优先重建受影响的 DerivedData 或单个任务状态。
4. 不从疑似损坏的缓存继续增量构建。
5. 不执行主动卸载、弹出或要求重新插拔 X5 的诊断步骤。
