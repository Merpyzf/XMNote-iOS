# 热力图亚像素布局导致圆角裁切和边缘错位

## 问题现象与最小复现

阅读卡片中的热力图左侧方格圆角像被切掉，表头与网格边缘还会出现细小错位。增加外层 padding 可以改变现象，但不同屏宽下仍不稳定。

最小复现：在自适应阅读卡片宽度下显示多周热力图，选择会让单格反算结果落在半像素的屏幕尺寸；放大观察首列 RoundedRectangle 和 header/grid 右边缘。

## 事实链

- 真实 owner 是 `HeatmapChart` 的几何反算，不是父卡片或颜色资源。
- 原始单格大小由 `(viewport - spacing)/weekCount` 得到，结果可能不落在物理像素网格。
- 单格、header、grid 和分段填充曾使用不同测量/几何通道，误差会在一行中累计。
- padding 只能掩盖某个尺寸，不能修正 raw square 与物理像素的关系。

## 根因机制

SwiftUI 用 point 表达尺寸，而显示设备按 `displayScale` 映射到像素。密集网格反算得到的 point 小数进入圆角裁切和多列累计后，会落在像素边界之间，使抗锯齿和 clip 边缘呈现不对称。

## 触发条件与影响范围

- 触发：自适应视口、可见周数反算、非整像素单格、RoundedRectangle/分段填充。
- 影响：热力图方格圆角、header/grid 对齐和左右边缘。
- 不影响：固定且本身落在像素网格的尺寸；热力图统计数据语义。

## 修复策略与取舍

从环境读取 `displayScale`，对视口和反算单格统一执行向下像素对齐；总行宽始终使用解析后的单格尺寸；header/grid 宽度也通过同一 snap；分段填充直接以解析后的 squareSize 分配高度。保留布局诊断日志，而不是继续叠加视觉 padding。

## 验证证据

- `a7641b45` 的实现同时记录 rawSquareSize、resolvedSquareSize 和 rowMinusViewport。
- 迁移总结给出 `floor(value * scale) / scale` 的最小示例和 Android density 对照。
- 当前组件仍由 `displayScale` 驱动 `resolveLayout`、视口测量和总行宽计算。

## 预防与边界

密集重复网格应让视口、单元和累计行宽同源并落在像素网格。只有出现新的独立组件案例且同样通过数值日志确认根因时，才考虑公共像素 snap 基础设施。
