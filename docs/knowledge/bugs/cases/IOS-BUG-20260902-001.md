# 书架整理工具栏选中后前景随 Liquid Glass 漂移

## 问题现象与最小复现

浅色模式下进入书籍整理，未选择时工具栏灰色稳定；选择一本后普通动作变为可用态，随封面滚动可能整体从深色切成白色，并在浅色玻璃上形成低对比度。

主书架或二级书架进入整理模式：不选择时滚动无异常；选择一本后连续向上滚动经过深色、浅色和高饱和封面，修复前普通图标与文字可整体变白。

## 事实链

- 真实 owner：xmnote/Views/MainTabView.swift, xmnote/Views/Book/Components/BookshelfEditingAccessory.swift, xmnote/Utilities/DesignSystem/SemanticColors.swift
- 真实写入点：MainTabView 读取根 colorScheme 并传给 BookshelfEditingAccessoryHost, BookshelfEditingAccessoryHost 为自定义 accessory 内容显式注入根 colorScheme, BookshelfEditingAccessoryView.ActionAppearance 根据 enabled/disabled/busy 映射具体项目语义色
- 生命周期/调用时机：tabViewBottomAccessory 创建系统玻璃宿主；选择状态使普通动作从次级灰切换到主语义前景；滚动改变玻璃下方内容并触发 accessory 局部外观重解析，导致动态主色漂移。
- 平台事实来源：
- Apple 文档确认 HierarchicalShapeStyle.primary/secondary 是当前内容样式层级，并非固定浅深语义色
- tabViewBottomAccessory 只承诺 accessory 放置和布局，不承诺自定义内容继承原生 Tab 项同等 vibrancy
- iOS 26.5 模拟器中降低透明度后修复前漂移消失，证明触发来自玻璃上下文解析

## 根因机制

可用态使用的动态主语义色在 tabViewBottomAccessory 的 Liquid Glass 局部环境中重新按下方内容解析；玻璃外壳和自定义前景不是同一条适配路径，选择后才进入差异明显的主色，因此出现白玻璃配白前景。

## 触发条件与影响范围

- 影响：主书架与二级书架整理模式中，选中书籍后的普通批量动作前景可读性与滚动稳定性。
- 不影响：选择逻辑、命令分发、业务写入、Tab Bar 最小化、系统玻璃外壳、删除红色、品牌绿色语义均未改变。

## 修复策略与取舍

保留系统 tabViewBottomAccessory 和玻璃外壳，从 MainTabView 捕获根浅深外观，仅向自定义整理工具栏内容注入该外观；普通动作使用项目 icon/text 主次语义色，危险动作保持 feedbackError。

## 验证证据

- ai-build 与 ai-run 在 Xcode 26.6/iOS 26.5 专属模拟器通过
- 浅色选中 1 本和 2 本跨多组封面滚动，普通动作持续为深色
- 深色选中 2 本滚动，普通动作持续为浅色
- 增强对比度浅色选中滚动，普通动作持续为深色
- 降低透明度下选中状态前景正确
- 主书架与在读二级书架选中后滚动均稳定
- XXXL 与最大辅助功能字号下工具栏文案未缩小或裁切
- design-system changed lint 无新增 enforced 违规
- git diff --check 通过
