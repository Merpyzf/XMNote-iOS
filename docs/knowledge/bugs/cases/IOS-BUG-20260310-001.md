# 时间线观察边界、diff 与富文本测量放大滚动成本

## 问题现象与最小复现

阅读时间线包含多组长富文本时，首屏和滚动明显抖动；日期或筛选数据刷新会牵连顶部日历重绘。早期为减层级加入的包装还破坏了日期 Section 的粘性头。

最小复现：准备多组含长 HTML 的时间线数据，进入页面后连续滚动并切换日期/筛选；观察折叠文本测量、日历桥接刷新以及分组标题是否持续吸顶。

## 事实链

- 页面容器同时观察日历状态、sections、loading 和富文本单元，观察 owner 过大。
- `sections` 即使内容等价也可能被重复写回，触发深层 diff。
- 折叠态仍走完整富文本解析与布局，且缓存没有覆盖宽度和行数约束。
- 为减少刷新添加的外层 equatable 包装改变了 `Section` 结构，导致 pinned header 失效。

## 根因机制

无关状态共享观察热区，使局部变化扩散到日历桥接和整个列表；重复写等价 sections 增加 diff；每个折叠单元在滚动热路径执行重测量。性能补丁又破坏了系统 `Section` 语义，形成新的行为回归。

## 触发条件与影响范围

- 触发：长时间线、多段 HTML、日期/筛选切换、列表滚动。
- 影响：首屏稳定性、滚动帧率、粘性日期头。
- 不影响：展开后的单条完整富文本能力；时间线 Repository 查询语义。

## 修复策略与取舍

拆分日历与列表观察边界；通过 `applySections` 阻止等价值重复写入并维护 revision；折叠态走轻量预览和包含尺寸约束的布局缓存；恢复原生 `LazyVStack(pinnedViews:) + Section(header:)` 结构。没有为了性能取消粘性头或完整展开能力。

## 验证证据

- `324f1a30` 记录五个相关文件的闭环改动和 `BUILD SUCCEEDED`。
- 提交差异可见 sections guard、calendar/list 拆分及 RichText 预热入口。
- 迁移总结明确记录粘性头回归的成因和系统尾部截断边界。

## 预防与边界

先缩观察 owner 和相同状态写入，再优化单元渲染；性能修复不得破坏 `Section`、pinned header 等容器语义。富文本完整态与列表预览态应被视为不同成本通道。
