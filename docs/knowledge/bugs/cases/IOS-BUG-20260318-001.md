# 横向分页异步生命周期导致混合内容查看崩溃

## 问题现象与最小复现

从阅读时间线打开包含书摘、书评和相关内容的混合查看器后，快速横向翻页会发生崩溃；同类查看页还存在错页、旧详情晚到和 selection 反复写回风险。

最小复现：时间线选择包含多类型内容的日期 → 打开混合内容查看器 → 在详情仍加载时快速连续横向翻页并越过窗口边界。

## 事实链

- 页面 ID 来自内容主键，真实分页 owner 应是可见 ID 集合和 selection 的共同宿主。
- 修复前 ContentViewer、NoteViewer 与日历各自复制 scroll position、窗口和 selection 提交逻辑。
- 详情加载 Task 挂在具体页面实现里，窗口重建后仍可能向已经失效的页面/模型状态写回。
- 时间线只是进入混合 feed 的触发入口，不是崩溃 owner。

## 根因机制

重复的分页状态机没有统一规定“滚动中只暂存位置、停止后提交 selection”以及“页面异步任务必须绑定稳定 ID”。窗口集合变化、业务 selection 和过期异步结果在不同实现中交错，最终让混合内容路径进入不一致页面状态并崩溃。

## 触发条件与影响范围

- 触发：混合 feed、详情异步加载、快速分页、窗口半径跨界。
- 影响：书摘/书评/相关内容查看以及复用相同宿主的横向页面生命周期。
- 不影响：单页静态查看；Repository 的内容查询和删除事务语义。

## 修复策略与取舍

抽取 `HorizontalPagingHost`，由稳定 ID 统一管理 scroll position、可见窗口、交互中 pending selection 和停止后的最终提交；页级加载与“成为选中页”分别绑定 `.task(id:)`；领域快照补齐 Sendable。保留窗口化懒加载，没有退回一次性构建全部详情。

## 验证证据

- `a6250ce2` 同时删除三个页面中的重复分页状态并引入统一宿主。
- ContentViewer 改为提供 `itemIDs + pageStateProvider`，异步入口收敛为 MainActor/Sendable 闭包。
- 提交说明明确记录时间线混合内容崩溃恢复与模拟器构建成功。

## 预防与边界

分页位置、业务 selection、窗口集合和页面 Task 必须共享同一个稳定 ID owner。复用基础设施本身不构成模式证据；只有新的独立崩溃证明同根因、同修复策略后才允许模式晋升。
