# 阅读日历分页手势竞争与状态写入放大

## 问题现象与最小复现

阅读日历月份较多、封面颜色异步回填时滚动掉帧，左右翻月还会偶发失效或被页内纵向内容截获。

最小复现：打开包含多个月份和多本书封面的阅读日历，在颜色仍处于 pending 时连续横向翻月并纵向滚动；观察掉帧、分页手势失效和页面抖动。

## 事实链

- 分页交互 owner 是外层页面容器，但旧实现为感知滚动又在月页叠加 `DragGesture`。
- 页面数据 owner 同时把全量月份映射成重 `MonthPage`，任一 selection 或颜色状态变化都会放大重算。
- 日格 payload 在月级预构建，颜色结果又逐条写回 `@Observable`，形成“计算放大 + 写入放大”。
- 卡顿与手势失效来自同一调用时段，但不是单一控件能力缺失。

## 根因机制

横向分页和子页拖拽存在识别竞争；同时全量重页面、整月 payload 预计算及逐条观察状态写入让 SwiftUI 在手势热路径中承担超出可见范围的 diff 与布局工作。

## 触发条件与影响范围

- 触发：分页容器内嵌滚动内容、月份数量较多、异步颜色密集回填。
- 影响：阅读日历翻月、滚动流畅度、颜色加载期间的稳定性。
- 不影响：静态单月展示；不参与分页手势的总结 Sheet。

## 修复策略与取舍

保留分页容器的全量索引，重内容只窗口化到当前月前后各一页；日 payload 下沉到格子绘制时计算；颜色回填批量提交；移除会抢占横向分页的子页 DragGesture。没有通过禁用分页或降低业务数据量规避问题。

## 验证证据

- 提交 `21d0c2a7` 显示 `monthPages` 从全量 `availableMonths.map` 改为 `visibleMonthWindow`。
- `DayPayload` 从整月字典预构建改为 `dayMap` 上的 `payload(for:)` 按需解析。
- 学习文档记录了手势冲突复现与 O(M) 到 O(W=3) 的计算边界变化。

## 预防与边界

分页容器必须是对应轴向手势的唯一 owner。性能优化先收缩可见数据与状态写入范围，不通过叠加手势监听或破坏分页语义实现。
