# 开发语言配置导致中文 key 显示英文资源名

## 问题现象与最小复现

中文模拟器中，全局搜索范围栏只有“书籍”显示为英文 `Books`，同一行“全部 / 书摘 / 相关”仍是中文。UI 控件和 enum 中都写的是中文源文案。

最小复现：将设备语言设为 `zh-Hans-CN`，进入全局搜索，观察通过 `String(localized: "书籍")` 生成的普通 String；同时检查构建产物包含的 `.lproj` 与工程 development region。

## 事实链

- 显示链为 `GlobalSearchScope.book.title → String(localized:) → XMScopeSelectorItem.title → Text(item.title)`。
- `Text(item.title)` 接收普通 String，不会再次以 SwiftUI 字面量 key 解析。
- 工程当时声明 `developmentRegion=en`，knownRegions 只有 `en/Base`，Bundle 实际没有可选中文目录。
- String Catalog 虽以 `zh-Hans` 为 sourceLanguage，但“书籍”保留了残缺英文值 `Books`。

## 根因机制

源码源语言、工程开发语言、最终 Bundle 可用语言和局部翻译条目彼此不一致。运行时只能在 Bundle 实际包含的 localization 中选择，因此中文用户偏好也命中英文资源；普通 String 组件如实显示了上游错误解析结果。

## 触发条件与影响范围

- 触发：中文用户环境、`String(localized:)`、Bundle 只有英文可用 localization、对应 key 有残缺英文值。
- 影响：需要普通 String 的 enum/model/UIKit/组件边界上的固定文案。
- 不影响：用户输入、书名等应原文展示的数据；直接 SwiftUI 字面量但没有错误翻译的文案。

## 修复策略与取舍

把 Xcode development region 与 known regions 统一为 `zh-Hans`；保持 String Catalog source language 为中文；删除半截英文 translation；用 `zh-Hans.lproj/InfoPlist.strings` 确保 Bundle 明确包含中文 localization。没有通过硬编码 `Text(verbatim:)` 绕过本地化系统。

## 验证证据

- `e73bf9be` 的工程差异明确将 `developmentRegion=en` 改为 `zh-Hans`。
- 学习总结保存完整调用链、Bundle 选择机制和资源职责边界。
- Apple 文档确认 preferred localizations 只来自 Bundle 已包含语言，development localization 来自开发语言。

## 预防与边界

本地化问题必须检查最终 Bundle，而不能只看 `.xcstrings` 源文件。英文上线必须作为完整语言包交付；业务数据不得进入本地化 key 通道。
