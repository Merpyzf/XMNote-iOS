# XMNote iOS AI Bug 问题库说明

## 1. 权威性与边界

`docs/knowledge/bugs/` 是 XMNote iOS 已验证生产缺陷及跨案例模式的权威数据源。Markdown/JSON Front Matter 是可审阅、可版本化的事实；`artifacts/ai-knowledge/index.sqlite` 只是当前 worktree 可删除、可重建的本地索引。

只收“证据化缺陷”：必须具有可重复错误行为或明确人工观察路径，并能确认真实 owner、真实写入点、触发时机、根因机制和验证结果。纯视觉微调、重构、功能增强、泛化优化及仅因提交类型为 `fix` 的修改不得入库。

Android 案例用于理解业务意图和工程方法，不能替代 iOS 当前代码、最小实验或 Apple 官方文档。

## 2. 目录

- `cases/`：一次真实修复一张案例卡。
- `patterns/`：至少两个独立案例证明同根因、同修复策略后的共性模式。
- `archive/`：保留被替代、失效或归档的历史。
- `artifacts/ai-knowledge/`：被 Git 忽略的 worktree 本地草稿、会话、索引和试运行指标。

空目录无需占位文件。当前没有满足晋升条件的模式，因此 `patterns/` 和 `archive/` 可暂时不存在。

## 3. 生命周期

```text
真实 Bug 输入
  → 检索案例/模式/规则/学习资料/Git
  → 复现、owner、写入点、生命周期、平台事实
  → 修复与验证
  → artifacts 本地草稿关闭
  → 用户明确“任务已完成”
  → 正式案例发布与知识闸门
  → 两个独立案例同根因、同策略
  → candidate
  → 用户批准 active
  → 必执行保护覆盖后 enforced
```

开发期禁止把草稿写进 `docs/`。`case publish` 和 `pattern propose` 必须显式提供 `--confirm-task-complete`，用于阻止误操作，不替代真实用户确认。

## 4. 案例与模式状态

案例：

- `closed`：事实闭环和验证已完成。
- `archived`：保留历史，但不再作为当前修复入口。

模式：

- `candidate`：两个以上独立案例证明同根因、同策略，尚未获得用户批准。
- `active`：用户已批准，适用/不适用边界明确。
- `enforced`：除 active 条件外，还被必执行测试、静态脚本、构建路径或 Git Hook 真实覆盖。
- `superseded` / `archived`：已被替代或停止使用。

文档或人工评审本身不能让模式成为 `enforced`。单案例评分再高也不能绕过抽象准入规则。

## 5. 常用命令

```bash
# 修复前检索
python3 scripts/ai-knowledge/kb.py search \
  --query "现象 触发条件 错误信息" \
  --paths xmnote/Views/Feature/File.swift

# 查看和维护开发期草稿
python3 scripts/ai-knowledge/kb.py draft list
python3 scripts/ai-knowledge/kb.py draft show DRAFT-YYYYMMDD-NNN
python3 scripts/ai-knowledge/kb.py draft update DRAFT-YYYYMMDD-NNN \
  --set 'root_cause="根因机制"'
python3 scripts/ai-knowledge/kb.py draft close DRAFT-YYYYMMDD-NNN

# 用户明确任务完成后的发布
python3 scripts/ai-knowledge/kb.py case publish DRAFT-YYYYMMDD-NNN \
  --confirm-task-complete

# 治理与评测
python3 scripts/ai-knowledge/kb.py validate
python3 scripts/ai-knowledge/kb.py audit
python3 scripts/ai-knowledge/kb.py eval
python3 scripts/ai-knowledge/kb.py metrics
bash scripts/verify_ai_bug_knowledge.sh
```

## 6. 检索与评测

检索先要求元数据、全文、关键词或相关路径至少有一项真实匹配，再应用类型和状态权重。无匹配模式不能靠固定类型分进入 Top N。交互式检索补充 `rg` 与 Git 历史；固定评测一次加载知识并批量排序，避免重复扫描污染耗时。

固定评测位于 `scripts/ai-knowledge/eval_queries.json`。每个种子至少包含两条同义改写和一条边界负例；负例只禁止对应错误案例进入结果，不要求整个仓库无任何相关资料。

当前 8 个历史种子的收口基线：

- 查询数：24。
- Recall@5：100%。
- MRR：0.9688。
- 负例误召回率：0%。

## 7. Hook 与 Git 试运行

`.codex/hooks.json` 是仓库工作流护栏：

- `SessionStart` 只提示入口、开放草稿和到期项。
- `UserPromptSubmit` 识别真实 Bug 并保存脏工作树哈希基线。
- `PreToolUse` 在每个新生产功能域首次写入前拒绝一次并返回检索命中。
- `Stop` 只检查相对基线产生的生产改动，并使用 `stop_hook_active` 防止无限续跑。

项目 Hook 需要用户在 Codex 中审查并信任；它不是完整安全边界。Git 进入 30 天 warning 试运行：缺少 `Knowledge-Case` 的 `fix` 提交只告警，非法或不存在的案例引用会阻止提交。

## 8. 维护与复审

- 路径失效、复审日期到期、重复根因和虚假 `enforced` 由 `audit` 报告。
- 案例修复策略变化时更新案例并重新计算指纹，不直接修改成想要的模式结果。
- 30 天后根据误拦截、草稿完成成本、实际复用和保护覆盖率决定是否申请严格门禁；升级必须再次获得用户明确批准。
