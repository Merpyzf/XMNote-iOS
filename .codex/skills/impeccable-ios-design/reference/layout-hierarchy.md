# Layout And Hierarchy

## 目标

让用户快速识别主任务、信息分组和可操作项，并在 XMNote 实际支持的设备与容器中保持稳定。

## 规则

- 先用亲密性、留白、对齐、字重、尺寸和分隔关系组织层级，不先增加容器。
- 卡片内部避免再套同权子卡片；同一总卡中的区块优先用分栏、divider 或间距分组。
- 亲密性优先于机械平均分布。相关文字、数字、图形和操作靠近；不同语义明确拉开。
- 避免页面充满等高、等宽、等结构的指标块；只有真实同类数据才使用同构布局。
- 覆盖项目支持的 iPhone 与 iPad、横屏与竖屏、Dynamic Type、安全区和不同容器宽度。
- 组件不要假设自己始终占满屏幕；在 sheet、导航内容区、分栏或嵌套容器中检查真实提案尺寸。
- 触控目标至少提供 44pt 交互热区，即使图标或文字的视觉尺寸更小。
- 需要几何计算时优先相对布局与阈值更新，避免依赖屏幕绝对宽度、连续几何回写或无界增长。

## 评审方法

- 代码可以确认固定 frame、无界网格、绝对屏幕宽度和点击热区等结构风险。
- 最终密度、层级和分组观感必须结合实际渲染；仅代码证据时标记“视觉风险，需截图验证”。
- 单个页面的间距问题默认局部修正；多个独立场景同根因时才考虑公共 spacing 或容器抽象。

## 反模式

- 卡片套卡片
- 无业务依据地复制“大数字 + 小标题 + 装饰图表”指标卡
- 所有区块使用相同 padding 和标题结构
- 为整齐牺牲主次层级
- 依赖 `UIScreen.main.bounds` 或只验证单一 iPhone 竖屏
