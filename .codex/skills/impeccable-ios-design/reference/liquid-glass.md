# Liquid Glass

## 设计定位

把 Liquid Glass 视为功能层和导航层的系统表达，不把它当作内容卡片的高级皮肤。涉及 iOS 26 新特性时，先读仓库 iOS 26 参考入口；涉及 API 或平台行为时，必须使用 `apple-doc-mcp` 查证。

工具不可用时，只能描述本地代码和设计风险，不得凭记忆补造 `glassEffect`、容器、交互或可用性结论。

## 默认策略

- 优先让标准系统组件获得系统提供的外观；只有标准表达不足且平台事实已确认时，才评估自定义玻璃。
- Liquid Glass 只承载浮在内容之上的功能和导航，不覆盖阅读正文、普通数据卡、列表卡或信息面板主体。
- 同层多个自定义玻璃元素需要根据官方语义评估容器和合并关系，不能机械地为每个元素单独套玻璃。
- 交互变体只用于真实交互控件；装饰元素不得伪装成交互层。

## 导航栏边界

- 系统导航栏上下文中的按钮已经由系统负责平台外观，禁止再显式添加 `.glassEffect(...)`、`.buttonStyle(.glass)`、`.buttonStyle(.glassProminent)` 或等价 glass/material 包装。
- 顶部 leading 返回入口复用 `TopBarBackButton`，不要为了玻璃效果手写返回按钮。
- 普通顶部 action 使用仓库既有组件和导航模式，不用额外玻璃层制造突出感。

## 允许评估的场景

- 内容上方的浮层操作
- 顶部或底部功能层中的局部控件
- 与系统功能层同层的瞬时操作区

这些场景只表示可以评估，不代表必须使用玻璃；先证明普通系统组件或现有材质无法满足层级与业务语义。

## 禁止场景

- 阅读正文容器、普通数据卡、列表卡和信息面板主体
- 为了装饰把整屏主要内容做成玻璃
- 系统导航栏按钮重复套 glass/material
- 没有官方事实和运行态验证时猜测 modifier 顺序、容器行为或交互语义
