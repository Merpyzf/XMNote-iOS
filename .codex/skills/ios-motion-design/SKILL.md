# iOS Motion Design

让 XMNote 的动效保持原生、克制、连续、可信。先把 Apple 官方设计与系统行为作为平台基线，再使用 Airbnb 的产品动效经验补充上下文连续性、对话感和规模化复用；不要复制任何品牌的视觉表面。

需要手势物理、速度连续性、空间路径、触感或 Reduce Motion 判断时，读取 `references/apple-fluid-motion-principles.md`。需要上下文保持、产品语气、可复用动效语义或 Lottie 边界时，读取 `references/airbnb-motion-principles.md`。

## 优先级

发生冲突时，按以下顺序决策：

1. 用户当次要求与 XMNote `AGENTS.md`
2. XMNote 已有生产页面、系统组件、导航模式、动效语义与无障碍行为
3. Apple HIG、WWDC 与官方 SwiftUI 行为
4. 本 skill 的 Apple 原生动效原则
5. Airbnb 的产品动效视角
6. 局部审美偏好

涉及 Apple API 可用性、参数语义、弃用或平台行为时，必须按仓库规则使用 `apple-doc-mcp` 查证。工具不可用时，不得用第三方文章或本 skill 补造平台事实。

## 先完成事实闭环

在选择动画 API 前，先核对：

1. 复现用户实际看到的状态变化或手势路径。
2. 找到真实状态 owner 与真实写入点，不把视觉现象直接归因于 View。
3. 确认触发动作、生命周期、异步完成或取消时机。
4. 标出持续保持身份的业务对象，以及只负责展示的临时视图。
5. 涉及平台行为时取得 Apple 官方事实来源。

没有完成这些核对时，不上升为公共动效基建，也不先发明全局 curve、transition 或 modifier。

## 动效决策顺序

### 1. 判断是否需要运动

- 只为结构变化、空间关系、状态反馈、操作结果或避免突兀跳变添加运动。
- 高频路径默认即时或极短；中频路径减少装饰；低频、首次或高情绪时刻才允许少量愉悦感。
- 键盘输入、连续滚动和高频切换不得因装饰性动画增加等待。
- 如果删除动画后信息仍同样清楚，优先删除或收缩动画。

### 2. 保持响应与直接操控

- 在交互开始时立即反馈，不等待异步结果或整段动画结束。
- 拖拽期间让内容连续跟随手势；以手势起点和相对位移为基准，避免对象突然吸附到触点中心。
- 不用动画门闩阻塞下一次点击、返回、取消或手势反向。
- 系统控件已提供合适反馈时，优先保留系统行为，不叠加重复缩放、弹跳或触感。

### 3. 保持空间与对象连续性

- 让同一业务对象在状态变化前后保持可追踪身份。
- 进入与退出沿一致路径；由某个来源触发的浮层或展开态应保留来源关系。
- 使用深度、缩放、阴影或模糊解释真实层级变化，不把它们当作“高级感”装饰。
- 大范围页面切换优先遵循既有导航关系，不用自造动画掩盖错误的 push、cover 或 sheet 选择。

### 4. 保证可中断与速度连续

- 快速重复触发、手势驱动或可逆状态必须能从当前可见状态继续，不从陈旧逻辑端点跳回重播。
- 手势结束后的落点同时考虑当前位置与运动方向/速度；不要只靠单一距离阈值，也不要机械移植其他平台的公式。
- 自定义边界交互使用渐进阻力表达“已到边界”；能复用系统滚动、分页或 sheet 物理时不自建。
- 只有手势本身携带动量或产品语气明确需要时才使用低幅回弹；普通生产路径默认干净落位。

### 5. 设计可访问的替代表达

- 每条有意义的运动路径都读取 `@Environment(\.accessibilityReduceMotion)`。
- Reduce Motion 保留状态、结果与层级反馈，减少大位移、缩放、视差、深度、动画模糊和长尾回弹。
- 优先替换为短淡入淡出、内容替换或即时状态变化；不得让关键反馈随动画一起消失。
- 直接跟随手势且帮助理解的反馈可以保留，但要降低非必要弹性与自动运动。

### 6. 协调视觉与触感

- 只在 commit、snap、成功、错误或重要选择等有明确因果的时刻使用触感。
- 让视觉落位、状态提交与触感发生在同一因果节点，不用触感补救迟到的视觉反馈。
- 尊重 XMNote 的触感设置与 Reduce Motion 策略；不要为普通点击默认增加触感。

## SwiftUI 实现路径

1. 局部状态变化优先使用 `withAnimation` 或 `.animation(_:value:)`，把动画限定到真实状态值。
2. 插入/移除使用 `transition`，内容值变化使用 `contentTransition`。
3. 同一语义对象跨容器、位置或尺寸变化时，使用稳定 ID 与 `matchedGeometryEffect` 保持身份。
4. 多阶段编排使用 `PhaseAnimator` 或 `keyframeAnimator`，并为不同属性明确时序职责。
5. 只有 SwiftUI 无法正确表达导航级交互取消、快照编排或系统集成时，才窄化使用 UIKit 自定义转场。
6. Lottie 只用于品牌插画、空状态、非阻塞完成时刻和图标级资产；不用它承担核心导航或信息架构转场。

## XMNote 起始参数

以下值是本项目的调参起点，不是平台定律，也不覆盖系统组件默认运动：

- 微反馈：`.snappy(duration: 0.18)`，用于选择、轻量状态确认和局部按压反馈。
- 结构变化：`.smooth(duration: 0.28)` 或低回弹 spring，用于展开、筛选和局部布局变化。
- 共享对象过渡：约 `0.28-0.36s`，使用稳定 ID 并确保源/目标确为同一语义对象。
- 滚动关联：只在阈值跨越时改变状态，不为每个 offset 更新附加动画。
- Reduce Motion：使用淡入淡出、短时内容替换或即时变化。

## 评审清单

- 这段运动响应哪个动作或状态写入？
- 谁是真实 owner，写入和取消分别发生在什么时候？
- 动画删除后会丢失哪条信息？
- 哪个业务对象从起点到终点保持身份？
- 快速重复点击、中途返回、手势反向和任务取消是否会跳变？
- 拖拽落点是否同时考虑位置和运动趋势？
- 是否误用了系统已经提供的导航、滚动、sheet 或控件反馈？
- 高频路径是否足够短，Rare delight 是否阻塞下一步操作？
- Reduce Motion 是否保留状态、结果和可操作性？
- 相同语义能否复用已有 timing、transition 或 motion spec？

## 反模式

- 因为页面“太静”而增加弹跳。
- 在父层挂宽泛动画，导致无关兄弟视图一起运动。
- 用动画等待掩盖加载、禁用、错误或完成状态缺失。
- 用自定义 overlay 动画绕开正确的系统导航关系。
- 同时叠加位移、旋转、缩放、阴影、模糊和 delay，却说不清各自职责。
- 只在正常速度下凭感觉验收，不检查重复触发、取消、Reduce Motion 与真机手势。

## 与其他 XMNote Skill 的边界

- 使用 `xmnote-design-system` 判断整个界面的设计真相、信息层级、字体、颜色、材质、布局、平台表达与公共能力准入是否成立。
- 使用 `ios-motion-design` 判断状态变化为什么运动、如何运动以及如何验收。
- 使用 `swiftui-expert-skill` 校准 SwiftUI API、状态管理、性能、并发和可访问性实现。
- 进行完整 SwiftUI UI 改造时按任务范围组合使用；不要让任一 skill 越权替代另一个 owner。
