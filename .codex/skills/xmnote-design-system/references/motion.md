# 动效与手势

本专题属于 `xmnote-design-system`，负责判断状态变化为什么运动、如何运动，以及如何验证。让 XMNote 的动效保持原生、克制、连续、可信；不复制任何品牌的视觉表面。

## 适用范围与参考

仅在任务涉及手势直操、转场、spring、matched geometry、keyframe、Lottie、触感、可中断性或 Reduce Motion 时读取。普通静态界面任务不自动加载本专题。

任务模式、授权、设计真相和公共能力准入沿用 [主 Skill](../SKILL.md)；发现步骤、构建与验证范围沿用 [工作流](workflow.md)，不启动第二套审批或收口流程。

- XMNote 的成熟组件、导航关系和已验证动效语义决定本地设计选择；平台行为结论仍需要 Apple 官方事实，已有页面不能覆盖平台事实。
- 需要手势物理、速度连续性、空间路径、触感或 Reduce Motion 判断时，读取 [Apple 原生动效原则](apple-fluid-motion-principles.md)。
- 用户明确要求 Airbnb 风格交互动效，或需要上下文保持、对话感、轻量产品个性、可复用动效语义或 Lottie 边界时，读取 [Airbnb 产品动效视角](airbnb-motion-principles.md)。把风格目标落实到当前交互的响应、对象连续性和属性编排，不凭品牌名称套用曲线。
- Apple 官方设计与系统行为是平台基线，Airbnb 是补充产品视角，不覆盖 XMNote 设计系统或 Apple 平台约束。第三方视角到 SwiftUI 的映射应标记为项目推断。
- Apple API 查证沿用 `AGENTS.md`：先尝试 `apple-doc-mcp`，不可用或不足时使用 Apple 官方文档或相关本机 SDK，注明来源、版本及局限；仍无法确认时仅暂停依赖该事实的部分。

## 先完成事实闭环

诊断已有运动路径或为其选择动画 API 时，核对相关事实；新功能使用预期状态变化和交互路径，不虚构既有故障复现：

1. 复现用户实际看到的状态变化或手势路径。
2. 找到真实状态 owner 与真实写入点，不把视觉现象直接归因于 View。
3. 确认触发动作、生命周期、异步完成或取消时机。
4. 标出持续保持身份的业务对象，以及只负责展示的临时视图。
5. 涉及平台行为时取得 Apple 官方事实来源。

公共动效抽象仍须满足仓库双场景准入；对已有 owner 的局部修正不要求先建设基础设施。证据不足时限制结论或暂停依赖该证据的选择，继续其他已授权工作。

## 动效决策顺序

### 1. 判断是否需要运动

- 添加运动前明确它改善的是结构理解、空间关系、操作确认、响应感，还是用户已明确的产品表达；“像 Airbnb”或“更高级”本身不是充分理由。
- 高频路径默认即时或极短，允许不增加等待的低幅按压、选择与状态反馈；中频路径减少装饰；更丰富的品牌编排优先留给低频、首次或高情绪时刻。
- 键盘输入、连续滚动和高频切换不得因装饰性动画增加等待。
- 删除动画前同时评估信息、对象连续性、操作质感与已明确的产品表达；静态信息仍清楚不代表微反馈没有价值。没有上述价值，或重复系统反馈、造成额外等待时，删除或收缩动画。

### 2. 保持响应与直接操控

- 在交互开始时立即反馈，不等待异步结果或整段动画结束。
- 拖拽期间让内容连续跟随手势；以手势起点和相对位移为基准，避免对象突然吸附到触点中心。
- 不用动画门闩阻塞下一次点击、返回、取消或手势反向。
- 系统控件已提供合适反馈时，优先保留系统行为，不叠加重复缩放、弹跳或触感。

### 3. 保持空间与对象连续性

- 让同一业务对象在状态变化前后保持可追踪身份。
- 进入与退出沿一致路径；由某个来源触发的浮层或展开态应保留来源关系。
- 使用深度、阴影或模糊解释真实层级变化；缩放也可表达低幅的直接操作反馈。各属性应有明确职责，不把它们当作“高级感”装饰。
- 大范围页面切换优先遵循既有导航关系，不用自造动画掩盖错误的 push、cover 或 sheet 选择。

### 4. 保证可中断与速度连续

- 快速重复触发、手势驱动或可逆状态必须能从当前可见状态继续，不从陈旧逻辑端点跳回重播。
- 手势结束后的落点同时考虑当前位置与运动方向/速度；不要只靠单一距离阈值，也不要机械移植其他平台的公式。
- 自定义边界交互使用渐进阻力表达“已到边界”；能复用系统滚动、分页或 sheet 物理时不自建。
- 只有手势本身携带动量或产品语气明确需要时才使用低幅回弹；普通生产路径默认干净落位。

### 5. 设计可访问的替代表达

- 自定义运动路径应由其 SwiftUI owner 读取或接收 `accessibilityReduceMotion`，让相关分支遵守统一策略；不要求每层视图重复声明环境值。复用系统行为时先查证其实际表现，不为满足清单而叠加自定义动画。
- Reduce Motion 保留状态、结果与层级反馈，减少大位移、缩放、视差、深度、动画模糊和长尾回弹。
- 优先替换为短淡入淡出、内容替换或即时状态变化；不得让关键反馈随动画一起消失。
- 直接跟随手势且帮助理解的反馈可以保留，但要降低非必要弹性与自动运动。

### 6. 协调视觉与触感

- 只在 commit、snap、成功、错误或重要选择等有明确因果的时刻使用触感。
- 让视觉落位、状态提交与触感发生在同一因果节点，不用触感补救迟到的视觉反馈。
- 尊重 XMNote 的触感设置与 Reduce Motion 策略；不要为普通点击默认增加触感。

## SwiftUI 实现路径

1. 局部状态变化优先使用 `withAnimation` 或 `.animation(_:value:)`，把动画限定到真实状态值。
2. 插入/移除使用 `transition`，内容值变化使用 `contentTransition`。
3. 同一视图树内同一语义对象的局部位置、尺寸或布局变化，可使用稳定 ID、共享 namespace 与 `matchedGeometryEffect`；核对源/目标身份和插入移除时机，不把它默认用于跨页面导航。
4. 列表到详情等跨页面变化先确认真实导航关系。系统默认转场合适时保留；需要从明确来源缩放进入、且平台与呈现方式适用时，评估 `matchedTransitionSource(id:in:)` 配合 `navigationTransition(.zoom(sourceID:in:))`。这些导航 API 自 iOS 18 起可用；不是所有详情都应改为 zoom，仍须核对返回、交互取消及 Reduce Motion。
5. 多阶段状态序列可考虑 `PhaseAnimator`；需要按属性精确编排时可考虑 `keyframeAnimator`。选择这些 API 不等于已经支持手势直操或可中断恢复，必须按实际路径验证。
6. 只有现有系统转场和 SwiftUI 路径无法满足已确认的导航级交互取消、快照编排或系统集成需求时，才窄化使用 UIKit 自定义转场。
7. Lottie 只用于品牌插画、空状态、非阻塞完成时刻和图标级资产；不用它承担核心导航或信息架构转场。

平台依据：[matchedGeometryEffect](https://developer.apple.com/documentation/swiftui/view/matchedgeometryeffect%28id%3Ain%3Aproperties%3Aanchor%3Aissource%3A%29)、[matchedTransitionSource](https://developer.apple.com/documentation/swiftui/view/matchedtransitionsource%28id%3Ain%3A%29)、[navigationTransition](https://developer.apple.com/documentation/swiftui/view/navigationtransition%28_%3A%29)、[ZoomNavigationTransition](https://developer.apple.com/documentation/swiftui/zoomnavigationtransition)。具体版本与行为仍按本次任务查证，不从 Airbnb 的历史 UIKit 实现推断 SwiftUI 能力。

## 复杂交互的最小编排说明

新增或改变多阶段动效、共享对象转场或自定义手势时，在当前回复或已有方案中简述以下相关决定，再实现并验证；审查时用它核对已有实现。普通微反馈、单参数调整或完整复用已验证系统行为，只说明本次改变及检查路径，无须展开整张表。底稿不要求另建文档、新建 motion spec 类型或新增公共组件。

| 决定 | 需要说明 |
| --- | --- |
| 主体与连续性 | 哪个对象保持身份，起止状态是什么；背景、文字等陪衬如何配合；涉及临时快照时何时交还真实视图 |
| 属性与时序 | 哪些属性确实需要变化，各自起止值、曲线及开始/结束关系；允许同时、重叠或分阶段，不为形式强加 delay |
| 手势与状态 | 哪段直接跟手，释放后如何选择落点；提交、取消、反向和重复触发如何接续当前状态；不为等动画而延迟本应立即发生的业务操作 |
| 可访问性与证据 | Reduce Motion 如何保留语义；哪些实际操作能验证本次编排，复用哪些已有证据 |

以局部卡片展开为例：卡片承担空间连续性，内容显隐配合可用空间变化，背景只解释层级；分别决定时序，收起或反向时从当前状态接续。这个例子不规定统一延迟、时长或导航方式。

## XMNote 起始参数

以下值是本项目既有的调参起点，不是平台定律，也不覆盖系统组件默认运动。实现先核对当前动效 owner，优先复用已有参数或组件；不直接把参考数值固化为全局 token：

- 微反馈：`.snappy(duration: 0.18)`，用于选择、轻量状态确认和局部按压反馈。
- 结构变化：`.smooth(duration: 0.28)` 或低回弹 spring，用于展开、筛选和局部布局变化。
- 共享对象过渡：约 `0.28-0.36s`，使用稳定 ID 并确保源/目标确为同一语义对象。
- 滚动关联：只在阈值跨越时改变状态，不为每个 offset 更新附加动画。
- Reduce Motion：使用淡入淡出、短时内容替换或即时变化。

这些数值不代表 Airbnb 的官方参数，也不能代替多属性编排。需要调整时按实际位移、交互频率和落点效果验证，不因落在建议时长内就判定质量合格。

## 按相关路径选用的评审清单

- 这段运动响应哪个动作或状态写入？
- 谁是真实 owner，写入和取消分别发生在什么时候？
- 动画改善了哪种理解、连续性、操作质感或已明确的产品表达，是否重复系统反馈？
- 哪个业务对象从起点到终点保持身份？
- 快速重复点击、中途返回、手势反向和任务取消是否会跳变？
- 拖拽落点是否同时考虑位置和运动趋势？
- 是否误用了系统已经提供的导航、滚动、sheet 或控件反馈？
- 高频路径是否足够短，Rare delight 是否阻塞下一步操作？
- Reduce Motion 是否保留状态、结果和可操作性？
- 相同语义能否复用已有 timing、transition 或 motion spec？

## 运行证据与交付

实际修改动效时，完成当前授权范围内的实现与必要检查，并按相关交互验证；只读审查不自动修改或构建。复用仍适用的运行证据，不为无关维度扩展设备矩阵或全量测试。

- 微反馈：检查正常触发、可重复操作和本次涉及的 Reduce Motion 分支；确认即时响应、不累积变形、不带动无关布局。无需完整多阶段录屏材料。
- 多阶段、共享对象或自定义手势：检查真实存在的进入/退出、快速重复、中途反向/取消、释放落位及 Reduce Motion 路径。优化已有交互时，在可取得的同等条件下比较前后表现。
- 对时序、跟手和中断作“已验证”结论，必须有实际操作观察记录或能看清相关过程的录屏；记录设备/系统、初始状态、操作路径和结果。手势记录还应能辨认起始位置与方向。截图只证明静态帧，编译和 lint 只证明其覆盖的结构规则。慢放可辅助定位接缝，正常速度用于判断节奏；没有测量时不声称达到某帧率或性能指标。
- 交付简述本次设计与实现选择、实际检查结果，以及未验证的路径；明确区分“静态检查通过”和“动效运行已验证”。缺少运行条件时完成独立的已授权工作，列明具体缺口，不把推断写成已验收，也不反复重试无关环境操作。

`policy.json` 的动画时长规则 `DSR002` 当前为 `report`，检查时长归属等静态线索；存在 motion owner 或 Reduce Motion 分支不能证明时序、中断恢复或可访问性已正确实现。Skill 的文字约束和格式校验同样不替代上述运行证据；不为宣称 AI 会遵守而擅自升级门禁。

## 反模式

- 因为页面“太静”而增加弹跳。
- 在父层挂宽泛动画，导致无关兄弟视图一起运动。
- 用动画等待掩盖加载、禁用、错误或完成状态缺失。
- 用自定义 overlay 动画绕开正确的系统导航关系。
- 同时叠加位移、旋转、缩放、阴影、模糊和 delay，却说不清各自职责。
- 对可重复、可取消的交互只凭正常速度作确定性验收，忽略相关重复触发、取消或 Reduce Motion 路径。模拟器不能证明的真机手势体验应列为未验证项，不据此自动部署真机。

动效的目的、产品语气、视觉关系与验收由本专题统一；涉及 SwiftUI API、状态管理、性能、并发或可访问性实现时，按需使用 `swiftui-expert-skill`。不因设计专题已合并而引入新的全局动画组件或改变依赖。
