# 设计语言

本参考负责 XMNote 的整体产品表达、信息层级、文案、适配和可访问性。具体排版与布局读取 [排版、间距与布局](typography-and-layout.md)，颜色与材质读取 [颜色、表层、图标与材质](color-surfaces-and-material.md)。

## 产品表达

XMNote 是以阅读内容和个人思考为中心的工具。界面应安静、清楚、内容优先，并用克制的绿色交互语义和少量品牌焦点建立识别；不是通过更多卡片、颜色、玻璃或装饰图表制造“设计感”。

- 书籍封面、书摘正文、个人想法和阅读数据是内容主角，容器退后。
- iOS 系统导航、控件、菜单、Sheet、Alert 和反馈行为优先；Android 只提供业务意图与信息结构，不能决定视觉和交互表达。
- 品牌焦点必须稀缺。页面同时出现多个同权绿色按钮、彩色图标或品牌标题时，先重新判断主任务。
- 已有页面只是证据，不自动等于规范。孤立样式、Debug 实验和历史异常不得被复制。

## 信息层级决策

新增或修改页面前，按顺序回答：

1. 用户此刻唯一最重要的任务是什么？
2. 完成任务前必须先理解哪一组内容？
3. 哪些信息只是解释、状态或元数据？
4. 哪个操作是主操作，哪些是次级、菜单或破坏性操作？
5. 哪些内容需要容器边界，哪些只需要亲密性和留白？

把答案映射为四层：

| 层级 | 内容 | 视觉处理 |
| --- | --- | --- |
| 主任务层 | 当前页面核心内容或唯一提交动作 | 最清楚的文字和位置；品牌强调最多保留一个 |
| 结构层 | 分区、列表主项、关键值与导航关系 | 通过标题、对齐、留白和系统容器建立 |
| 支撑层 | 描述、状态、筛选结果、次级动作 | 弱一档排版与中性色，但仍需可读和可操作 |
| 元数据层 | 时间、来源、计数、非关键标签 | 最低但可辨识；不承担风险、错误或主要入口 |

一个元素同时依靠更大字号、更粗字重、品牌色、卡片和阴影强调，通常意味着层级手段叠加过度。先保留最能解释业务重要度的一到两种手段。

## 亲密性、密度与容器

- 同一语义组内部距离小于组间距离；标题与说明、正文与元数据、标签与所属内容必须能从空间关系直接读懂。
- 对齐优先于装饰。先统一内容起始线、baseline、边缘和操作列，再考虑新表层。
- 卡片只表达真实分组、交互边界或浮起层级；不要把每段文字、每个指标和每个按钮都放入独立卡片。
- 不同重要度内容不能为了整齐做成等高、等宽、等颜色的指标矩阵。
- 空白是层级工具，不是待填满区域。没有业务含义的图表、渐变、插画和装饰文案不应进入生产页面。
- 页面看起来“散”时，先检查亲密性、对齐和容器宽度；看起来“挤”时，先检查信息数量和层级，不直接全局放大间距。

## 控件与操作层级

- 页面唯一提交、创建或确认动作可以成为主操作；普通导航、筛选、排序、更多和关闭保持次级。
- 不用品牌色把所有可点击元素都标成主操作。可点击性首先来自系统控件语义、位置、标签和反馈。
- 破坏性操作不与普通操作并列伪装；使用明确动作词、对应反馈色和必要确认。
- 成功优先通过内容、选择、导航或按钮状态变化表达；不要默认增加“已完成”“已更新” Toast。
- 失败、不可执行或需要用户决策时必须给出可感知反馈，且反馈层级与决策成本匹配。

## 产品文案

先判断展示组件，再判断片语还是完整句子；不要机械全局替换标点。

| 场景 | 规则 |
| --- | --- |
| 按钮、菜单项、导航标题、分区标题、字段标签、placeholder、选项、角标、短状态 | 使用简短片语，不加句末标点 |
| 单句且简短的辅助说明、设置描述、空状态、Toast、Banner、行内提示、Sheet 补充说明 | 通常不加结尾 `。` 或 `.` |
| Alert 标题 | 片语不加句末标点；问句保留 `？` |
| Alert 补充消息 | 使用完整句子和恰当句末标点 |
| 通知 | 标题简短且不加句末标点；正文使用完整句子和标点 |
| 多句说明、长段落、法律或风险说明、App Intent 完整描述 | 使用完整书面标点 |

- 按钮使用结果明确的动作词，例如“删除”“保存”“继续”，避免“好的”“确定一下”等模糊表达。
- 中文语境使用全角 `，。；：？！“”‘’（）`，中文标点前后不加空格；URL、时间、小数、版本号和代码内部保持 ASCII 语法。
- 进行中状态使用单个 `…`；正文中的语义省略使用 `……`，禁止 `...`。
- 中文界面术语使用 `“”`，书名使用 `《》`；标签和值已由布局分隔时不机械追加冒号。
- 删除界面已经表达的信息、重复标题、空泛引导和无行动价值的成功文案。
- 用户输入、外部原文、文件名、URL、协议值、代码和日志不机械改写。

## 本地化与文本边界

- 完整句子及其标点一起进入字符串目录，不在调用处拼接跨语言标点。
- 修改源文案键时同步维护 `Localizable.xcstrings` 现有元数据。
- 日期、时间、数字和单位使用本地化格式化 API，不用字符串拼接假设中文顺序。
- 用真实最长文案检查导航标题、按钮、菜单、设置值、状态卡和 Sheet 标题；不要只用短中文验证。
- 文案被截断时，先判断是否应换行、缩短、调整布局或移动到详情，不通过缩小到不可读字号解决。

## 平台表达与适配

- 当前 Tab 内继续深入属于 push；必须覆盖 TabView 并保留底层现场属于 full-screen cover；只补充当前任务参数、选择或确认才使用 Sheet/popover/Alert。
- 不自造与系统导航、Alert、Menu、Picker、分享面板或 scroll-edge 相似的替代控件。
- iPhone 小屏、大屏、横屏、安全区、键盘、iPad 规则宽度和分屏都按内容优先级适配，不使用 Android 式固定断点机械翻译。
- 普通页面避免固定屏宽和文本固定高度；需要最大阅读宽度时由页面容器或 canonical scaffold 统一管理。
- 主要能力不能为了适配而隐藏。空间不足时优先重排、换行、转为菜单或使用系统紧凑表达。
- 底部固定操作、Tab Bar 和手势区共存时，滚动内容必须自然进入安全区并保持可达，不能生硬裁切。

## Dynamic Type 与可访问性

- 所有生产文本响应 Dynamic Type；品牌字体、UIKit 测量和离屏渲染也必须与 SwiftUI owner 同源。
- 辅助功能字号下检查水平行是否需要转为多行或纵向，不能依赖固定行高、单行截断或过低 `minimumScaleFactor`。
- 主要辅助信息使用可读的语义色；同时缩小字号、降低对比度和远离主内容会造成三重弱化。
- 原生交互控件保留自然的 VoiceOver label/value/hint；装饰图标隐藏，组合控件按任务语义分组。
- 颜色、动画或位置变化不得成为传递状态的唯一方式。
- Reduce Motion 下保留结构关系和结果反馈，去除非必要位移、弹跳和连续装饰运动。
- 点击区按 [组件与交互](components-and-interaction.md) 的 44pt 默认基线和受控例外处理。

## 反模板化检查

出现以下任一迹象时暂停抛光，先修正信息结构：

- 每个分区都有独立卡片、图标和标题，但用户任务没有因此更清楚。
- 到处是渐变、玻璃、阴影、胶囊和品牌色，缺少明确焦点。
- 所有内容同权，主操作、次级动作和状态提示视觉相近。
- 用装饰性统计、插画或大数字填补空白，却没有支持用户决策。
- Android 布局、Web dashboard 或通用 AI 模板的视觉结构被直接移植。

不能只说“丑”或“AI 感”。评审必须指出具体证据、受影响任务、真实 owner、最小修正和截图验证方式。
