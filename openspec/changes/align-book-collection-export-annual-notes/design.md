## Context

Android 书单详情页在更多菜单中提供 `书籍导出`，点击后把当前书单内有效书籍 ID 传入通用批量导出页；但 Android 文案没有明确“当前书单”，且导出页清空选择会退化为“全部书籍”，存在范围歧义。Android 年度书单复用 `collection_book.recommend` 存储单本书的关系备注，但 UI 文案仍叫 `收藏理由`，没有体现年度阅读总结语境。

iOS 当前书单详情的真实 owner 是 `BookCollectionDetailView`，状态编排在 `BookCollectionDetailViewModel`，书籍 Item 与备注区在 `BookCollectionVisualComponents`，备注编辑 Sheet 在 `BookCollectionSheets`。详情页右上角更多菜单目前主要承载手动书单的对象级操作；底部 Liquid Glass 浮层已经稳定承载高频 `添加书籍`。`collection_book.recommend` 已通过 Repository 读取和写入，年度 relation 创建时该字段为空，当前阻止年度书单编辑备注的主要原因是 UI 把备注编辑权限绑定到了 `viewModel.isManual`。

## Goals / Non-Goals

**Goals:**

- 在书单详情页补齐 `导出此书单` 入口，手动书单和年度书单都能触达。
- 入口阶段只给出明确占位反馈，不启动半成品导出、分享或文件选择流程。
- 年度书单允许编辑单本书的年度个人点评，并与普通书单 `收藏理由` 形成清晰语义区分。
- 复用现有 relation 字段和 Repository 写入口，不新增数据库迁移。
- 保持 iOS 现有信息层级：底部浮层仍只服务高频添加书籍，内容卡片不新增 Liquid Glass。

**Non-Goals:**

- 不实现真实批量导出、导出格式选择、字段选择、文件生成或系统分享。
- 不调整 Android 导入、微信读书书单导入、占位书转正等其他未对齐能力。
- 不改变年度书单成员同步策略、排序规则或读完年份计算。
- 不新增单元测试或 UI Test；本阶段按仓库默认以构建校验和手动场景核查为主。

## Decisions

### 1. 导出入口放在详情页更多菜单

`导出此书单` 是书单对象级、低频、跨模块动作，放入详情页右上角更多菜单最符合现有层级。它不应进入底部 Liquid Glass 浮层，因为底部浮层已经是手动书单高频主操作 `添加书籍`；也不应进入书籍 Item 的 context menu，因为导出范围是整本书单。

替代方案：放到底部第二个浮层按钮。放弃原因是会和 `添加书籍` 抢主操作、增加底部遮挡，并且导出不是高频动作。另一个替代方案是跳转 `PersonalRoute.batchExport`，放弃原因是该路由是个人页泛导出入口，不能表达当前书单上下文。

### 2. 导出入口先做占位反馈

点击 `导出此书单` 时，ViewModel 只设置现有顶部反馈 banner，提示导出模块迁移中。实现不得打开系统分享、文件选择器或半成品路由，避免用户进入没有真实结果的流程。详情为空或书单无书时仍可保留入口，但反馈文案应避免暗示已经执行导出。

替代方案：先打开一个空导出页。放弃原因是它会制造“功能可用”的误导，并且容易继承 Android 的范围歧义。

### 3. 年度点评复用 `collection_book.recommend`

`recommend` 是书单-书籍 relation 文本，天然能表达“这本书在这个书单里的主观记录”。年度书单点评复用该字段，可以保持 Android 数据结构对齐，不引入 schema/migration 风险。UI 层通过上下文把同一字段映射为不同文案：手动书单是 `收藏理由`，年度书单是 `年度点评`。

替代方案：新增 `annual_note` 字段。放弃原因是 Android 无对应字段，会引入迁移、同步和双端语义分叉，而且当前需求只需要区分展示语义。

### 4. 拆分结构编辑权限与 relation 文本编辑权限

现有 `isEditable` 同时控制移出、排序、备注入口等行为，无法表达“年度书单结构只读，但点评可编辑”。实现应拆成结构编辑权限和 relation 文本编辑权限：手动书单两者都可用；年度书单只允许 relation 文本编辑，不允许添加、移出、排序或编辑书单本体。

替代方案：继续用 `isManual` 控制全部编辑。放弃原因是会阻止年度点评落地，且语义过粗。

### 5. 年度状态文案从 `只读` 调整为 `自动同步`

年度书单不是整页不可操作，而是“书籍成员由读完记录自动同步”。内容标题区继续用轻量状态徽标，但文案应从 `只读` 调整为 `自动同步`，避免和可编辑年度点评冲突。

## Risks / Trade-offs

- 年度点评可能因读完年份变更被清空 → 本轮不改同步策略；实现时在代码注释或后续需求中记录，如果产品要求保留历史点评，需要另起数据同步修复。
- 导出入口可见但不可实际导出 → 使用明确占位 banner，避免打开任何半成品导出流程。
- 同一字段两种文案可能让代码命名继续沿用 `recommend` → 保持底层命名与 Android 对齐，UI 层新增 relation 文案上下文，避免在业务文案中泄漏内部字段名。
- 更多菜单在年度书单也显示后可能增加顶部视觉存在感 → 菜单仍是系统 toolbar 控件，不新增内容层按钮；年度菜单仅包含导出这类对象级操作。

## Migration Plan

本变更不需要数据库迁移。实现可按 UI/VM 层最小改动发布；如果出现问题，可回滚为仅手动书单显示更多菜单，并恢复年度 Item 不显示点评编辑入口，底层数据不会受影响。

## Open Questions

- 后续真实导出是否需要包含书单 relation 文本：Android 当前只导出书籍实体字段，不导出 `recommend`；iOS 后续导出设计应明确“仅导出书籍信息”还是“导出书单关系信息”。
- 年度点评在读完状态改错再改回后是否必须保留：若必须保留，需要调整年度 relation 复用或恢复策略。
